# UI accessibility and interaction

Identify the user's primary flow and review it with real content and failure states.
Use semantic buttons, links, labels and headings. Give icon-only controls an accessible name.
Keep keyboard focus visible and logical. Dialogs need an accessible title, focus management and a close action.
Check text contrast, reduced motion, zoom, long names, empty data, loading, errors and disabled states.
Keep touch targets usable and avoid horizontal overflow at supported sizes.
Verify that every visible action reaches its stated outcome and reports failures.
Use a bundled approved browser runner when available. If it is unavailable, distinguish code inspection from executed UI testing.
Record reproducible findings with paths, lines, user impact and a suggested fix. Do not modify unrelated design choices.
Apply fixes only through the host's approved project file tools.
