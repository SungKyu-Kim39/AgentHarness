# Developer documents

Read the request, repository instructions, existing design and relevant code first.
Choose only the document required by the task. Do not create a document workflow for a simple answer.
Separate requested behavior, implemented behavior, tested behavior and outstanding decisions.
Record interfaces, data ownership, failure behavior and trust boundaries when they affect implementation.
For an API, describe inputs, outputs, error handling and a concrete example consistent with actual code.
For a validation report, include OS, artifact hash, model endpoint type, command and observed result.
Write concisely in the user's language. Ask only questions that change scope or block dependent work.
Propose project file changes through the host approval tool. Do not claim a document was saved until the tool succeeds.
