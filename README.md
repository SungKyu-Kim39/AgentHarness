# Ned

Ned는 사내 Qwen 모델에 **Zed 편집기, 전용 OpenCode 엔진, Aegis·Conductor·OpenViking과 오프라인 도구**를 연결하는 Windows x64 바이브 코딩 작업 환경이다. 개별 도구의 설치·설정을 직원에게 맡기지 않고 한 프로그램으로 제공하는 것을 목적으로 한다.

[소개와 활용](docs/ned-introduction.md) · [설치 안내](docs/offline-setup.md) · [모델 설정](docs/model-controls.md) · [구성과 승인 경계](docs/architecture.md) · [라이선스](docs/license-policy.md) · [개발 인계](HANDOFF.md)

## 현재 상태

0.3.6 변경: 설치 위치 선택(업데이트 시 기존 경로 기본), Windows 알림 영역의 프로젝트 폴더 열기(실제 바탕화면·즐겨찾기), compact 데스크톱 snapshot 형식 처리, 장시간 사용 후 종료 진단을 추가한다. Windows 편집기 내부 Open Folder는 내부 선택창을 사용해 보고된 네이티브 콜백 예외 경로를 피한다. 정확한 예외 원인은 미확정이다. [0.3.6 검증 범위](docs/validation-0.3.6.md)를 따른다.

[Ned 0.3.6을 배포했다](https://github.com/SungKyu-Kim39/AgentHarness/releases/tag/v0.3.6). 업데이트 후 **알림 영역 Ned 우클릭 → 권한 → 전체 권한** 또는 대화 입력창의 권한 선택 항목으로 지원 도구의 반복 승인창을 생략할 수 있다. 선택은 즉시 적용되며 새 대화·프로젝트·재시작·업데이트 후에도 유지된다. [설치 EXE·반입 TGZ](downloads/README.md)와 공개 다운로드 전체 해시 검증 기록을 제공한다.

0.3.5는 대화 입력창과 알림 영역에 **권한 → 전체 권한** 메뉴를 추가한다. 선택한 모드는 재시작·업데이트 후에도 유지하며 지원 도구의 반복 승인창을 생략한다. [권한 모드](docs/approval-modes.md)를 따른다.

[Ned 설치 EXE·폐쇄망 반입 TGZ](downloads/README.md)에서 최신 배포본과 검증 기록을 받는다. 0.3.4의 JSONC 시작 오류 수정도 유지하며 기존 0.3.3용 실행 패치는 추가 적용하지 않는다.

0.3.4에는 JSONC 번들 시작 오류 수정과 OpenViking 내보내기 도구 수정이 기본 포함된다. 원본 0.3.3 설치본의 `Cannot find module './impl/format'` 실행 오류는 JSONC 하위 모듈 누락에 따른 배포 결함이다. [0.3.3 실행 수정 패치와 적용 순서](downloads/README.md)를 사용한다. 설정·대화·지식은 삭제하지 않는다. 원본 EXE/TGZ는 그대로 보존하며 패치가 별도로 필요하다.

0.3.6은 Zed 기반 검증 후보이며 설정 JSON 가져오기 후 자동 재시작과 빈 시작 화면을 제공한다. 새 실행기·ACP·저장하지 않은 편집 내용 보호·기존 데이터 보존 이관을 구현하였으며, 실제 OpenCode 엔진을 사용하는 Linux 연동 검사에서 확인하였다. Windows 설치·편집기 화면·실제 MSBuild 실행·사내 모델과 외부망 차단 수용은 별도 확인 대상이다. [검증 상태](docs/validation-0.3.6.md)를 따른다.

검은 배경에 흰색 굵은 Ned 글자의 새 아이콘을 사용한다. 번들 Zed는 구성 요소의 원래 이름을 유지한다. [Ned 설치 EXE·반입 TGZ 다운로드](downloads/README.md)에서 새 후보와 이전 L-Vibe 0.2.7 기록을 구분한다.

## 0.3.1 시작 수정 패치

[시작 수정 패치 1](docs/ned-startup-fix-1.md)은 배포 PC에서 확인한 Windows AppData 경로 오류와 강제 프로젝트 선택을 수정한다. 원본 0.3.1 EXE와 구분하여 적용한다. 패치 후에는 시작 화면에서 폴더를 열고 AI 접근 범위를 승인한다. 사용자가 패치 적용 후 Ned의 실제 실행 성공을 확인하였다. 0.3.2에는 이 수정이 기본 포함된다.

## 사용하는 흐름

1. 반입용 TGZ를 압축 해제하고 포함된 Ned 설치 EXE를 실행한다.
2. 최초 설정 JSON에 사내 LLM과 단일 임베딩 모델을 입력한다.
3. Ned의 시작 화면에서 폴더를 열거나 최근 프로젝트를 선택하고 AI 프로젝트 접근을 승인한다.
4. 시작 안내창의 단계 표시를 확인하고, Zed에서 코드를 직접 편집·저장하고, **Ctrl+Shift+A**로 Ned AI 대화를 연다.

AI 수정은 별도 승인과 충돌 확인을 거친다. 저장하지 않은 편집 내용이 있으면 먼저 Ctrl+S로 저장한다. VS2017/2019가 있으면 AI가 설치된 MSBuild와 프로젝트 구성을 조사한 뒤 승인을 받아 빌드할 수 있다. SDK·모델 가중치와 개발 도구를 직원 PC에서 자동 설치하지 않는다.

여러 LLM과 모델별 한도·thinking 변형을 중앙 JSON으로 설정한다. 모델 서버 대기열을 고려하여 응답 대기에 기본 시간 제한을 두지 않는다. OpenViking은 앱과 함께 시작·종료하며, 기본 스킬 36개를 자동 등록한다. 개인 대화는 자동 업로드하지 않는다.

agent-desktop 1.2.0을 기본 포함하며, 창을 지정한 접근성 관찰과 앱 실행·접근성 관찰·의미 기반 UI 동작 20종을 호스트에서 중계한다. 각 호출에 별도 승인과 세션 귀속을 적용한다. [기능과 제한](docs/agent-desktop.md)을 따른다.

## 개발과 검증

`npm run build`는 Ned 실행기와 ACP 어댑터를 빌드한다. 고정 OpenCode 소스·Bun 의존성과 Windows 오프라인 런타임이 먼저 필요하다. [빌드·인계 절차](HANDOFF.md)를 따른다. 완전한 Windows 수용 전에는 1.0 완료 또는 폐쇄망 검증 완료로 표시하지 않는다.

0.3.2의 에이전트 도구·MCP 이름은 `ned_host_*`·`ned_*`로 통일한다. 현재 리소스 경로와 기본 스킬 안내도 Ned를 사용한다. 기존 기록과 개인 지식 저장소는 보존한다.

## 브랜치 운영

`main`은 배포 기준 소스·문서·배포 기록을 담는 기본 브랜치다. `work`에서는 개발과 검증을 이어가며, 검증된 릴리스 단위로 `main`에 반영한다. 현재 배포 기준은 Ned 0.3.3이다.

현재 승인 옵션과 적용 범위는 [승인 안내](docs/approval-modes.md)를 따른다.

0.3.3은 최초 설치 EXE 옆의 `agent-config.json` 자동 준비와 현재 대화·프로젝트의 파일 수정 자동 승인을 추가한다. 기존 설정은 보존하며 [승인 모드](docs/approval-modes.md)에서 범위와 해제 방법을 설명한다. 데스크톱 시간 초과 후 연결을 폐기·재생성하고 GUI 앱 실행을 제공한다. 실제 Windows 원인 판별과 계산기 조작은 배포 PC에서 추가 확인한다.

0.3.3은 편집기·대화창 글꼴과 패널 배치·키맵·작업공간 상태를 업데이트 후에도 보존하며, 실행 중인 편집기의 Windows 아이콘에도 Ned 이미지를 적용한다.
