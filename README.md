# Ned

Ned는 사내 Qwen 모델과 Zed 편집기, OpenCode 에이전트, 개발 도구와 지식 저장소를 한 번에 설치하는 Windows용 바이브 코딩 환경입니다. 직원이 도구마다 설치법을 익히고 설정 파일을 연결하는 수고를 줄이기 위해 만들었습니다.

Zed에서 코드를 직접 편집하면서 Ned에 코드 조사, 수정, 빌드, 문서 작성을 요청할 수 있습니다. 필요한 런타임과 스킬은 폐쇄망 반입 전에 묶어 두고, 모델 연결 정보는 중앙 JSON에서 관리합니다.

## 다운로드

최신 버전은 [Ned 0.3.7](https://github.com/SungKyu-Kim39/AgentHarness/releases/tag/v0.3.7)입니다. [설치 EXE와 반입용 TGZ](downloads/README.md)에서 파일과 체크섬을 받을 수 있습니다. 이전 버전과 수정 패치도 같은 페이지에 보관합니다.

0.3.7에서는 기본 스킬을 66개로 늘리고, 요청과 대화 문맥에 맞는 지침을 자동으로 불러오도록 했습니다. Python SDK의 파일 배치와 호스트 번들을 정리해 설치 부담도 줄였습니다.

| 항목 | 0.3.6 수정 빌드 1 | 0.3.7 |
| --- | ---: | ---: |
| 설치 EXE | 1,176,899,012 bytes | 1,040,612,708 bytes |
| 설치 후 파일 수 | 94,237개 | 55,926개 |
| 설치 시간 | 50.497초 | 38.935초 |

설치 시간은 같은 Windows Server 실행기에서 이전 버전과 새 버전을 차례로 설치한 결과입니다. 직원 PC의 Windows 10·11에서는 하드웨어와 보안 프로그램에 따라 달라질 수 있습니다. 검사 환경과 남은 확인 항목은 [0.3.7 검증 기록](docs/validation-0.3.7.md)에 정리했습니다.

## 처음 사용하는 방법

1. 반입용 TGZ를 새 폴더에 풀고 Ned 설치 EXE를 실행합니다. 설치 화면에서 D 드라이브 등 다른 위치를 선택할 수 있으며, 필요한 폴더는 설치기가 만듭니다.
2. 사내 LLM과 임베딩 모델을 설정합니다. 최초 설치 후 편집할 준비 파일은 `%APPDATA%\Ned\config-import.json`입니다. 설치 전에 EXE 옆 `agent-config.json`을 작성해 두었다면 그 내용이 자동으로 복사됩니다.
3. Ned를 실행하고 알림 영역의 **Ned → 프로젝트 폴더 열기**에서 작업할 폴더를 선택합니다.
4. Zed에서 코드를 열고 **Ctrl+Shift+A**로 Ned 대화를 시작합니다.

설정 변경은 **Ned → 설정 JSON 가져와 적용 (자동 재시작)**을 사용합니다. 저장된 설정이 있으면 설치 폴더의 JSON만 고쳐서는 바뀌지 않습니다. [설정 파일의 역할과 변경 절차](docs/configuration-recovery.md)를 확인하세요.

## 코드와 도구를 함께 다루는 방식

Ned는 선택한 프로젝트의 코드를 읽고 검색한 뒤 수정안을 만듭니다. 사용자가 직접 편집하고 Ctrl+S로 저장하는 동작은 일반 IDE와 같습니다. AI가 파일을 바꿀 때는 프로젝트 범위와 외부 변경, 저장하지 않은 편집 내용을 확인합니다.

반복 승인창이 번거롭다면 대화 입력창이나 알림 영역의 **권한** 메뉴에서 **프로젝트 파일 자동 승인** 또는 **전체 권한**을 선택할 수 있습니다. 선택은 재시작과 업데이트 후에도 유지됩니다. 적용 범위는 [권한 안내](docs/approval-modes.md)에 설명했습니다.

기본 구성에는 Aegis·Conductor 지침, 스킬 66개, Serena·clangd, Graphify, REA와 개발 MCP 6종이 들어 있습니다. VS2017/2019가 설치된 PC에서는 MSBuild와 솔루션 구성을 찾아 지원하는 빌드 작업을 실행할 수 있습니다. 필요한 SDK와 프로젝트 의존성은 미리 준비해야 합니다.

OpenViking은 Ned와 함께 시작하고 종료합니다. 기본 스킬을 등록하고, 사용자가 선택해 색인한 문서와 가져온 개인 지식을 검색합니다. 새 대화나 프로젝트 전체를 자동으로 업로드하지 않습니다. [스킬 안내](docs/skills-0.3.7.md), [개인 지식 이관](docs/openviking-personal-migration.md), [데스크톱 도구](docs/agent-desktop.md)에서 세부 사용법을 볼 수 있습니다.

## 개발과 배포

Ned 호스트는 설정과 승인, 서비스 실행·종료를 관리합니다. Zed는 편집기와 대화 화면을, 전용 OpenCode 엔진은 에이전트 실행을 담당합니다. 모델 가중치는 포함하지 않으며, 답변과 임베딩 계산에는 JSON에 지정한 사내 API를 사용합니다. 긴 서버 대기열을 고려해 모델 응답에 기본 시간 제한을 두지 않습니다.

빌드는 고정 OpenCode 소스와 Windows 런타임을 준비한 뒤 진행합니다. `npm run ned:prepare:acp`로 빌드 의존성을 준비하고, `npm run build`로 호스트와 ACP를, `npm run ned:release`로 0.3.7 설치기를 생성합니다. 자세한 절차와 코드 위치는 [개발 인계](HANDOFF.md), [아키텍처](docs/architecture.md), [어댑터 명세](docs/adapters.md)를 참고하세요.

`work`에서 개발과 검증을 진행하고, 검증한 배포본을 `main`에 반영합니다. 현재 배포 기준은 0.3.7입니다. Windows Server 설치·로딩 검사와 직원 PC의 실제 GUI·사내 모델·외부망 차단 검사는 구분하며, 1.0 전체 검증은 아직 완료하지 않았습니다.
