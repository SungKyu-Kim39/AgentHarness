# Ned 설치와 첫 실행

현재 배포 버전은 0.3.7입니다. 스킬 66개와 관련 런타임을 함께 반입하므로 직원 PC에서 npm·pip·uvx·Bun 설치나 Git clone을 할 필요가 없습니다. TGZ의 `source/`에는 대응 소스와 재현 자료가 있으니 묶음 전체를 보관하세요.

지원 대상은 Windows 10 1903 이상·Windows 11 22H2 이상 x64입니다. 실제 사내 OS와 보안 정책에서 확인한 범위는 [검증 기록](validation-0.3.7.md)을 참고하세요.

## 설치하고 설정하기

1. `Ned-0.3.7-windows-x64.tgz`를 새 폴더에 풉니다.
2. 기존 Ned·L-Vibe와 개인 Zed를 완전히 종료한 뒤 설치 EXE를 실행합니다. 기본 위치는 `%LOCALAPPDATA%\Programs\Ned`이며, `D:\Programs\Ned` 같은 전용 폴더를 선택할 수 있습니다. 폴더와 상위 경로는 설치기가 자동으로 만듭니다. 일반 사용자 설치로 관리자 권한을 요구하지 않습니다.
3. 최초 설정을 편집합니다. EXE 옆 `agent-config.json`이 있으면 설치기가 `%APPDATA%\Ned\config-import.json`으로 복사합니다. **설치 후 편집할 파일은 이 준비 사본입니다.** 배포 폴더의 원본을 나중에 바꿔도 이미 복사한 내용은 갱신되지 않습니다. 설치 전에 원본을 완성했다면 바로 다음 단계로 진행하면 됩니다. 원본 파일이 없으면 기본 예제를 준비합니다.
4. Ned를 실행합니다. 설정을 검증하고 암호화한 뒤 빈 시작 화면을 엽니다. 알림 영역의 **Ned → 프로젝트 폴더 열기**에서 작업 폴더를 선택하고, **Ctrl+Shift+A**로 대화를 시작합니다. 모델은 대화의 선택 메뉴에서 바꿀 수 있습니다.

여러 LLM은 JSON의 `providers`, 임베딩 모델 한 개는 `openViking.embedding`에 지정합니다. 실제 서버 주소·키·모델 ID를 입력하고 끝 쉼표나 Markdown 코드 블록 표시는 넣지 마세요. [모델 설정](model-controls.md)에 thinking 옵션과 대기 시간 설정도 설명했습니다.

## 설정 파일이 사라져도 정상인 경우

`config-import.json`은 최초 가져오기용 평문 파일입니다. 검증과 암호화 저장에 성공하면 삭제하고 `settings.enc.json`을 남깁니다. 이후에는 암호화 파일을 직접 편집하지 않고 **Ned → 설정 JSON 가져와 적용 (자동 재시작)**으로 새 JSON을 가져옵니다.

가져오기에 성공하면 편집기의 저장 확인을 거쳐 서비스와 앱을 다시 실행합니다. 설치 폴더의 예제 JSON만 고쳐서는 저장 설정이 바뀌지 않습니다. [설정 복구 안내](configuration-recovery.md)에 파일별 역할과 오류 처리 절차가 있습니다.

이미 암호화 설정이 있으면 업데이트나 재설치 때 설치 EXE 옆 JSON으로 덮어쓰지 않습니다. 손상이나 복호화 실패도 자동 초기화하지 않습니다. 배포 폴더의 원본 JSON은 사용자가 관리하는 파일이므로 실제 키를 넣은 뒤 보관과 폐기를 관리해야 합니다. 지원 채팅이나 공개 저장소에는 키를 보내지 마세요.

## 설치 위치와 데이터 보관

설정·기록·지식은 `%APPDATA%\Ned`에 저장합니다. 업데이트는 등록된 설치 위치를 사용하고 사용자 자료는 보존합니다. 설치 드라이브를 바꿔도 데이터 폴더가 함께 이동하지는 않습니다.

설치 대상은 전용 폴더여야 합니다. 드라이브 루트, 다른 파일이 든 폴더와 사용자 자료 폴더 내부는 거절합니다. 위치를 옮길 때는 기존 프로그램을 제거한 뒤 새 경로에 설치하세요. 기본 제거 과정에서도 사용자 데이터는 남깁니다.

기존 L-Vibe 자료가 있으면 앱 종료를 확인한 뒤 Ned 폴더로 복사하고 원본은 보관합니다. 기존 Ned 설정은 덮어쓰지 않습니다. 최초 이관을 준비할 때만 `%LOCALAPPDATA%\Ned-Launcher`를 사용하며, 복사한 프로필의 암호화 키를 사용하기 위해 Ned 데이터 경로로 한 번 재실행합니다. 다른 Windows 사용자 계정에서 복호화하지 못한 설정을 자동 초기화하지 않습니다.

## 프로젝트와 편집기 사용

알림 영역의 프로젝트 열기는 실제 Windows 바탕화면·즐겨찾기를 탐색합니다. 편집기 내부 Open Folder는 내부 경로 선택창을 사용합니다. AI가 접근하는 프로젝트 범위는 선택한 폴더로 제한합니다. 보고된 Windows 네이티브 폴더 선택 콜백 예외를 피하기 위한 구성이며, 정확한 내부 원인은 아직 확인하지 못했습니다.

사용자는 일반 IDE처럼 코드를 직접 편집하고 Ctrl+S로 저장합니다. AI 수정은 제안과 권한 확인, 기준 내용 비교와 스냅샷을 거칩니다. 편집기에서 저장하지 않은 내용과 디스크가 다르면 먼저 저장하도록 요청합니다.

반복 승인은 대화 입력창이나 **Ned → 권한**에서 조절합니다. **전체 권한**은 지원하는 파일 수정·빌드·지식·데스크톱 도구의 승인창을 생략하며, **프로젝트 파일 자동 승인**과 **승인 요청**도 선택할 수 있습니다. 0.3.3부터는 승인창의 **현재 대화·프로젝트 자동 승인**으로 같은 대화의 후속 수정을 잠시 허용할 수도 있습니다. [권한 안내](approval-modes.md)에서 차이를 확인하세요.

첫 실행 시 `%APPDATA%\Ned\editor\config\AGENTS.md`에 한국어 응답 기본 지침을 추가합니다. 기술 용어·고유 명사는 필요한 영어를 허용하고, 기존 지침은 보존하며 같은 블록을 중복 추가하지 않습니다.

## 시작과 종료

Ned가 준비되는 동안 아이콘과 현재 단계를 보여 줍니다. 설정·프로젝트 선택창이 열리면 안내창을 잠시 숨기고 편집기 프로세스가 시작되면 닫습니다. 진행 표시는 남은 시간을 계산한 백분율이 아닙니다.

개인 Zed는 먼저 종료하고 Ned를 실행하세요. Windows의 기본 Zed 인스턴스 제약이 있어 동시 실행은 별도 확인 항목입니다. 편집기에서 저장을 마치고 모든 창을 닫으면 OpenCode와 OpenViking도 함께 종료합니다.

OpenViking은 서비스 실행, 기본 스킬 등록, 자료 색인과 검색을 각각 확인합니다. 알림 영역에서 상태를 보고, 작은 문서 하나로 색인·검색을 시험해 보세요. 등록 실패 기록은 `%APPDATA%\Ned\openviking\skills-status.json`과 `model-status.json`에 남습니다. 등록 중 중복 재시도는 피하고 실패 후 **기본 스킬 등록 재확인**을 사용합니다.

## 이전 버전에서 업데이트할 때

편집기·대화 패널의 배치와 크기, 글꼴, 시작 방식과 키맵은 유지합니다. 현재 `editor/config/settings.json`을 JSONC로 읽고, 이전 appearance 설정은 현재 파일이 없을 때만 이관합니다. 최초 보완 전에는 `settings.before-ned-0.3.3.jsonc`에 보관하며 작업공간 DB 경로도 유지합니다.

새 설치본에는 0.3.1의 AppData·빈 시작 화면 수정, 0.3.3의 설정·ACP 수정과 0.3.4의 JSONC 시작 수정, 0.3.6의 축약 스냅샷 처리가 포함됩니다. 과거 버전용 패치를 추가 적용하지 마세요. L-Vibe 0.2.7에는 번들 Zed가 없으므로 Ned 설치 파일인지 확인해야 합니다.

시작·등록 오류는 [Windows 진단 안내](windows-diagnostics.md), 기존 OpenViking 자료 내보내기는 동봉한 `CHECK_EXPORT.cmd`와 [개인 지식 이관 안내](openviking-personal-migration.md)를 참고하세요. 파일명과 배포 경로는 ASCII를 사용하며 한국어 UI와 문서 내용은 유지합니다.
