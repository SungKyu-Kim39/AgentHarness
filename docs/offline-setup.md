# Ned 폐쇄망 설치와 사용

대상은 Windows 10 1903 이상 / Windows 11 22H2 이상 x64이다. 실제 사내 OS·보안 정책에서의 수용 결과는 [검증 상태](validation-0.3.3.md)에서 확인한다.

1. 반입용 `Ned-0.3.3-windows-x64.tgz`를 새 폴더에 압축 해제한다.
2. 기존 L-Vibe와 Zed를 완전히 종료한 뒤 포함된 Ned 설치 EXE를 실행한다. 일반 사용자 설치이며 관리자 권한을 요구하지 않는다.
3. 최초 설치 시 EXE와 같은 폴더의 `agent-config.json`이 있으면 사용자 준비 파일로 자동 복사한다. Ned 최초 실행에서 검증·암호화하여 적용하므로 별도 가져오기는 필요 없다. 파일이 없으면 기존처럼 기본 예제를 열어 편집한다. 여러 LLM은 `providers`, 임베딩 한 개는 `openViking.embedding`에 입력한다. 끝 쉼표와 Markdown 코드 표시를 넣지 않는다.
4. Ned를 실행하면 빈 시작 화면이 열린다. 폴더 열기·최근 프로젝트 선택 후 AI의 프로젝트 접근 범위를 승인한다. Zed에서 Ctrl+Shift+A로 Ned 대화를 연다. 모델은 대화의 모델 선택 항목에서 선택한다.

설치 경로는 `%LOCALAPPDATA%\\Programs\\Ned`, 설정·기록·지식 데이터 경로는 `%APPDATA%\\Ned`이다. 최초 데이터 이관을 준비하는 실행만 `%LOCALAPPDATA%\Ned-Launcher`를 사용하고, 복사 후 Ned 프로필로 한 번 재실행하여 기존 암호화 키를 함께 사용한다. 파일·경로 이름은 ASCII를 사용하고 한국어 내용·UI는 유지한다. 직원 PC에서 npm·pip·uvx·Bun 설치나 Git clone을 수행하지 않는다.

기존 암호화 설정이 있으면 설치 옆 JSON으로 덮어쓰지 않는다. 배포 폴더의 원본 JSON은 보존하며, JSON 오류나 암호화 실패는 자동 초기화하지 않는다.

최초 준비 설정은 `%APPDATA%\\Ned\\config-import.json`이다. 검증·암호화 저장에 성공하면 삭제되므로 `settings.enc.json`만 남는 것은 정상이다. 이후 설정 변경은 알림 영역의 **Ned → 설정 JSON 가져와 적용 (자동 재시작)**으로 수행한다. 가져오기가 성공하면 편집기의 저장 확인을 거쳐 서비스와 Ned를 자동으로 재시작한다. 설치 폴더의 예제 JSON 수정만으로 저장 설정이 바뀌지 않는다. 실제 키를 지원 문서나 공개 저장소에 올리지 않는다.

기존 L-Vibe 데이터가 있으면 기존 앱 종료를 확인하고 Ned 전용 폴더로 복사한다. 원본은 남겨 두며, 기존 Ned 설정을 덮어쓰지 않는다. 다른 사용자 계정에서 복호화하지 못하는 설정을 자동 초기화하지 않는다. 업데이트·기본 제거는 사용자 데이터를 보존한다.

코드는 일반 IDE처럼 직접 편집하고 Ctrl+S로 저장한다. 수동 저장은 AI 승인 대상이 아니다. AI 수정은 제안·승인·저장 내용 비교·스냅샷을 거친다. 0.3.3부터 승인창의 **현재 대화·프로젝트 자동 승인**으로 새 메시지까지 파일 수정 승인을 유지할 수 있다. 알림 영역에서 상태 확인·해제가 가능하다. 저장하지 않은 편집기 버퍼와 디스크가 다르면 AI 수정을 보류한다.

OpenViking 등록 상태는 알림 영역에서 확인한다. LLM 대화 성공, 서비스 실행, 기본 스킬 등록, 실제 색인·검색 성공은 각각 확인한다. 작은 문서 하나를 승인하여 색인하고 검색 결과를 확인하는 방법으로 시작한다.

Ned 편집기에서 파일 저장을 확인하고 모든 창을 닫으면 OpenCode·OpenViking을 함께 종료한다. Windows의 기본 Zed 인스턴스 제약 때문에 개인 Zed를 먼저 종료하고 Ned를 실행한다. 상호 동시 실행은 Windows 수용 항목이다.

시작 시 Ned 아이콘과 실행 단계가 표시된다. 설정·프로젝트 선택 창이 열리면 안내창은 잠시 숨겨지고, 편집기 프로세스가 시작되면 닫힌다. 진행 막대는 남은 시간을 보장하는 백분율이 아니다. 긴 최초 무결성 검사나 모델 서비스 준비 중에도 현재 단계를 확인할 수 있다. 설치 EXE는 Ned 버전인지 확인한다. 기존 L-Vibe 0.2.7에는 번들 Zed가 없다.

등록 실패 시 `%APPDATA%\Ned\openviking\skills-status.json`과 `model-status.json`의 단계·코드·HTTP 상태를 확인한다. 키·본문은 포함하지 않는다. 등록 중에는 중복 재시도를 하지 않으며, 실패 후 트레이의 기본 스킬 등록 재확인 메뉴를 사용한다.

시작 수정 패치 1 이후에는 프로젝트 선택을 강제하지 않고 Zed 시작 화면을 먼저 연다. 폴더 열기·최근 프로젝트 선택 후 AI 프로젝트 범위를 승인한다. 원본 0.3.1 설치본과 수정 패치의 차이 및 확인된 Windows 경로 오류는 [시작 수정 안내](ned-startup-fix-1.md)를 따른다.

최초 실행 시 `%APPDATA%\Ned\editor\config\AGENTS.md`에 한국어 응답 기본 지침을 추가한다. 기술 용어·고유 명사는 필요한 영어 사용을 허용하며 중국어·일본어 등 다른 언어로 답하지 않도록 지정한다. 기존 파일 내용은 보존하고 동일 블록은 중복 추가하지 않는다. Ned 엔진의 기본 지침에도 같은 규칙을 적용한다.

0.3.3부터 업데이트 후에도 편집기·대화 패널의 위치와 크기, 글꼴·글자 크기, 사용자가 지정한 시작 방식과 키맵을 보존한다. 설정은 주석·끝 쉼표를 지원하는 JSONC로 읽으며 현재 `editor/config/settings.json`을 우선한다. 이전 appearance 파일은 설정 파일이 없는 경우에만 초기 이관에 사용한다. 최초 보완 시 기존 설정을 `settings.before-ned-0.3.3.jsonc`로 한 번 보관한다. 창 배치 DB는 같은 사용자 데이터 경로에 유지한다. 새 설치의 빈 시작 화면 기본값은 유지하며 사용자가 선택한 시작 방식은 다시 덮어쓰지 않는다. 실행 중인 편집기의 Windows 창·작업표시줄·Alt-Tab 아이콘도 Ned 이미지를 사용한다.
