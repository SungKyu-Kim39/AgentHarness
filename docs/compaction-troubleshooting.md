# 대화 요약의 출력 한도 오류

Ned 0.3.8은 긴 대화를 압축할 때의 출력 한도 처리를 보완합니다. 이 문서는 `Compaction summary reached the output token limit` 메시지를 다룹니다.

## 어떤 오류인가

번들 OpenCode의 요약 처리에서는 모델의 최종 종료 사유가 `length`이면 이 오류를 만듭니다. 요약이 중간에 잘렸기 때문에 완료된 요약으로 저장하지 않는 것입니다. 서버 응답 대기 시간이 길다는 이유만으로 발생하는 메시지는 아닙니다. 연결 중단·HTTP 오류·사용자 취소는 별도로 처리합니다.

가능한 조건은 다음과 같습니다.

- 모델 정의의 `limit.output`이나 실제 요청의 출력 여유가 작은 경우입니다. 컨텍스트 한도를 크게 설정해도 출력 한도가 함께 커지는 것은 아닙니다.
- 서버가 적용하는 실제 생성 한도가 클라이언트 설정보다 낮은 경우입니다.
- reasoning·thinking이 출력 예산을 많이 사용한 경우입니다. 서버에 따라 추론 토큰도 생성 한도에 포함합니다.
- 긴 작업의 모든 기록과 코드·도구 출력을 자세하게 반복해 요약이 길어진 경우입니다.

메시지만으로 이 중 하나를 사용자 서버의 확정 원인이라고 단정할 수는 없습니다. 현재 엔진의 요청을 실제로 검사했을 때 요약에도 일반 도구 정의가 함께 실리는 것을 확인했으므로, 0.3.8에서는 이를 제거해 요약 작업에 필요한 요청만 보냅니다.

## 0.3.8에서 달라지는 처리

엔진의 마지막 요약 지시를 확인한 요청에만 간결한 요약 형식을 적용합니다. 원래 대화 내용은 바꾸지 않고, 미결 요구·결정·작업 상태·다음 행동·필수 경로를 남기도록 요청합니다. 일반 답변이나 도구 출력에 요약이라는 단어가 있다는 이유로 전환하지 않습니다.

요약 요청에는 도구 정의를 빼고 `tool_choice: none`을 지정합니다. Qwen 모델은 요약할 때 기본적으로 `reasoning_effort: none`, `chat_template_kwargs.enable_thinking: false`를 보냅니다. 일반 대화에서 선택한 thinking variant는 유지합니다. 실제 동작은 서버의 해당 필드 지원 여부에 따릅니다.

요약 응답은 완료 사유를 확인한 뒤 엔진에 전달합니다. `length`로 잘리면 기본 한 번만 더 짧게 요청하며, 이 재요약은 파일 수정이나 도구 실행을 반복하지 않습니다. 두 번 모두 잘리거나 응답이 불완전하면 오류를 알리고 기존 대화를 유지합니다. 잘린 응답의 종료 사유를 `stop`으로 바꿔 성공으로 처리하지 않습니다.

재요약에는 추가 모델 호출 한 번이 필요합니다. 서버가 usage를 제공하면 두 호출의 사용량을 합산해 전달합니다. 서버가 사용량을 누락하면 누락된 토큰을 추정해 채우지 않습니다. 사내 모델 대기열을 위한 기본 응답 시간 제한은 추가하지 않습니다. 사용자는 대기를 중지할 수 있습니다.

## 선택 설정

다음은 `agent-config.json`의 최상위 선택 항목입니다. 생략하면 아래 기본값을 사용합니다.

기존 `providers` 등의 항목과 같은 깊이에 넣고, JSON 항목 사이에는 쉼표를 둡니다. 마지막 항목 뒤에는 쉼표를 붙이지 않습니다.

```json
"compaction": {
  "maxOutputTokens": 8192,
  "retryOnLength": true,
  "disableQwenThinking": true
}
```

`maxOutputTokens`는 요약 요청의 상한입니다. 모델의 `limit.output`과 엔진이 남은 컨텍스트에 맞춰 계산한 출력 여유보다 높게 요청하지 않습니다. 예를 들어 모델 출력 한도가 4096이면 이 항목만 8192로 바꿔도 실제 요청은 4096을 넘지 않습니다.

출력 한도를 늘리려면 모델 서버 담당자가 확인한 범위 안에서 `providers.<공급자>.models.<별칭>.limit.output`도 설정합니다. `limit.context`에는 입력과 출력을 합친 실제 서버 한도를 사용합니다. 모델의 이름에서 최대 토큰을 추정하거나 임의로 큰 수를 넣지 않습니다.

자동 재요약을 원하지 않으면 `retryOnLength`를 false로 설정합니다. 서버가 Qwen 전용 thinking 필드를 거절하면 `disableQwenThinking`을 false로 바꾸고 서버가 지원하는 모델 옵션을 사용합니다. 수정한 JSON은 **설정 JSON 가져와 적용 (자동 재시작)**으로 가져옵니다.

## 계속 실패할 때

1. 설치 파일과 알림 영역의 버전이 0.3.8인지 확인합니다.
2. 모델의 context·output과 서버 출력 한도가 서로 맞는지 확인합니다.
3. `%APPDATA%\Ned\model-gateway-status.json`의 고정 코드를 확인합니다. `NED_COMPACTION_RETRY`는 출력 한도로 재요약을 요청한 기록이며, `NED_COMPACTION_OUTPUT_LIMIT`는 재요약 뒤에도 잘린 경우입니다. `LV_MODEL_UPSTREAM_RESET`·HTTP·연결 코드는 다른 실패 경로입니다.
4. 필요하면 작업의 결정·남은 일을 프로젝트 문서로 정리하고 더 짧은 요약을 요청합니다. 진행 중인 대화 DB나 지식 폴더를 삭제해 해결하려고 하지 않습니다.

진단 공유에는 고정 코드와 상태만 사용합니다. 대화 전문·모델 요청 본문·설정 파일·API 키는 보내지 않습니다.
