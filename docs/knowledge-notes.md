# Ned Agent에서 지식 쌓기

Ned에 “이 빌드 절차를 이 프로젝트에 기억해줘” 또는 “이 커밋 규칙을 모든 내 프로젝트에 기억해줘”라고 요청합니다. **승인 요청**과 **프로젝트 파일 자동 승인** 모드에서는 승인창에서 저장할 내용과 범위를 확인하며, **전체 권한** 모드에서는 팝업 없이 바로 로컬 OpenViking에 저장하고 설정한 사내 임베딩 서버로 색인합니다. 새 개인 저장소는 첫 저장 시 준비됩니다.

프로젝트 지식에는 설계 결정, 장애 해결 방법, 빌드 절차를 기록합니다. 개인 공통 지식에는 여러 프로젝트에서 참고할 규칙과 사용자의 작업 선호도를 기록합니다. 다른 프로젝트에서 앞서 저장한 공통 지식을 요청하면 Ned Agent가 찾아볼 수 있습니다. 프로젝트 지식은 저장한 프로젝트에서 검색합니다.

“Ned에 저장한 프로젝트 지식 목록을 보여줘”, “방금 저장한 빌드 절차를 수정해줘”, “이 지식을 삭제해줘”처럼 요청할 수 있습니다. 갱신과 삭제도 같은 [권한 설정](approval-modes.md)을 따릅니다. 동일한 범위와 제목은 기존 지식의 갱신으로 처리합니다. Ned는 관련 지식의 출처를 표시하며, 사용자가 별도로 요청한 원문이나 요약만 저장합니다. 기존에 가져온 OpenViking 개인 자료는 계속 읽을 수 있습니다.

OpenViking은 [모델·임베딩 설정](offline-setup.md)이 적용된 상태에서 사용합니다. 파일을 직접 색인하는 방식도 유지됩니다.

## 저장·검색 오류 진단

지식 저장·검색에 실패하면 `OV_EMBEDDING`(임베딩 모델 연결·모델 ID 오류), `OV_EMBEDDING_DIMENSION`(벡터 차원 불일치), `OV_FORBIDDEN`(403 권한 거부), `OV_TIMEOUT`(응답 시간 초과), `OV_TLS`(인증서 오류), `OV_SERVER_ERROR`(5xx 서버 오류) 등 세부 오류 코드를 반환합니다. 실패한 요청의 HTTP 상태·경로와 토큰·개인 경로를 마스킹한 응답 요약은 `%APPDATA%\Ned\openviking\request-diagnostics.json`과 `model-status.json`에서 확인할 수 있습니다. 임베딩 모델 주소·키·ID·차원을 다시 확인한 뒤 **Ned → 설정 JSON 가져와 적용 (자동 재시작)**으로 반영하세요.
