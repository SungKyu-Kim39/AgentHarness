# 기존 개인 Zed Agent 대화 가져오기

Ned 0.3.9 트레이의 **기존 Zed Agent 대화 가져오기**에서 개인 Zed의 `threads.db`를
선택하고 가져오기를 확인합니다. 일반적인 원본 경로는
`%LOCALAPPDATA%\Zed\threads\threads.db`입니다. 데이터 경로를 따로 지정했던 Zed는
그 경로의 파일을 선택합니다. 가져온 대화 목록은 Ned를 정상 종료하고 다시 열어 확인합니다.

Ned는 원본을 읽기 전용으로 열고 SQLite 백업 API로 일관된 사본을 만듭니다. 따라서 원본
DB와 함께 남아 있는 WAL의 확정된 대화도 포함합니다. 원본 파일이나 개인 Zed 설정은
변경하지 않습니다. 가능하면 개인 Zed에서 작업을 저장하고 종료한 뒤 진행하세요.

Ned DB는 `%APPDATA%\Ned\editor\threads\threads.db`입니다. 기존 Ned DB를 먼저
백업하고 트랜잭션으로 새 대화를 병합합니다. 같은 ID·내용은 중복으로 세고, 같은 ID에
다른 내용이 있으면 기존 Ned 대화를 유지하고 충돌로 보고합니다. 서로 다른 프로젝트의
대화도 가져올 수 있지만 파일 경로의 존재나 프로젝트 실행 환경까지 복원하는 기능은 아닙니다.

원본 사본과 가져오기 전 백업은 `%APPDATA%\Ned\editor\history-backups`에 남습니다.
백업에도 개인 대화가 있으므로 개인 데이터와 같은 방식으로 보관합니다. 모델 지정은 현재
Ned 모델 목록을 사용하도록 초기화하고 이전 대화의 sandbox 승인 기록은 제거합니다.
API 키·개인 Zed 설정·Ned/OpenCode 대화·프로젝트 파일은 복제하지 않습니다.

지원 기준은 Zed 1.28.1의 `threads` SQLite 스키마와 직렬화 버전 `0.3.0`입니다.
JSON·zstd 형식을 지원하며 부모 대화·폴더 메타데이터를 유지합니다. 다른 버전·손상된
행은 제외 개수로 보고합니다. 로컬 일반 DB 파일 1 GiB, 대화 20,000개, 행의 압축 데이터
16 MiB·해제 데이터 32 MiB 한도를 적용합니다. 지원하지 않는 자료를 성공으로 표시하거나
원본을 덮어쓰지 않습니다. 원본 Zed의 매우 오래된 다른 대화 저장 형식은 별도 이관이 필요합니다.
