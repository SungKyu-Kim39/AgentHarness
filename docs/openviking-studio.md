# Ned에서 OpenViking Studio 열기

Ned 0.3.8부터 알림 영역의 Ned 아이콘을 우클릭하고 **OpenViking Studio 열기**를 선택하면 지식 관리 화면이 열립니다. Ned가 실행한 OpenViking 0.5.5의 번들 화면을 사용하므로 별도 Studio 설치나 인터넷 접속이 필요하지 않습니다.

OpenViking을 JSON에서 활성화하고 임베딩 모델을 설정한 뒤 사용합니다. 서비스가 꺼져 있거나 시작·이관에 실패한 상태이면 새 서버를 임의로 띄우지 않고 상태를 알려줍니다. 먼저 **OpenViking / 기본 스킬 등록 상태**에서 준비 상태를 확인하세요.

## 어떤 자료를 보는가

이 창은 현재 Windows 사용자의 Ned 저장소 안에서 `ned` 계정의 자료를 관리합니다. 프로젝트 자료, 사용자 영역, 기본 스킬과 세션 자료를 살펴볼 수 있습니다. 가져온 예전 세션은 OpenViking 자료이며, Zed의 새 대화 목록으로 변환되지는 않습니다. Ned가 현재 대화를 자동으로 OpenViking에 업로드하는 기능도 켜지지 않습니다.

Studio는 사람이 직접 조작하는 관리 화면입니다. 가져온 사용자 영역도 확인할 수 있도록 해당 로컬 계정의 관리 범위를 사용합니다. 에이전트 도구에는 이 권한을 전달하지 않으며, 모델의 프로젝트·개인 검색 범위는 기존대로 유지합니다. 사용자가 Studio에서 자료를 직접 수정·삭제하는 동작은 에이전트의 파일 수정 승인창과는 별개입니다.

자료를 관리할 때는 다음 순서가 편합니다.

1. 리소스·사용자·스킬 영역에서 찾으려는 경로를 선택합니다.
2. 원문과 요약·색인 상태를 구분해 확인합니다. 파일이 보인다는 사실만으로 임베딩과 검색까지 끝났다고 판단하지 않습니다.
3. 기본 스킬을 수정하면 Ned의 다음 등록 검사에서 사용자 수정본으로 판단해 덮어쓰지 않을 수 있습니다. 팀 지침을 추가하려면 [확장 안내](extension-guide.md)를 먼저 확인하세요.
4. 이관 전 원본과 `%APPDATA%\Ned\openviking\namespace-backups`는 새 자료와 검색을 확인한 뒤 보관 정책에 따라 관리합니다. 활성 데이터 폴더를 탐색기에서 직접 옮기거나 바꾸지 않습니다.

## 연결과 창의 수명

실행할 때마다 배정한 127.0.0.1 포트와 앱 내부 인증으로 연결합니다. 키나 포트 번호를 사용자가 복사할 필요는 없습니다. 실제 인증 키는 호스트에서 요청에 넣으며 Studio의 JavaScript나 주소창·localStorage에 넣지 않습니다. 원본 UI의 연결 확인을 위해 `ned-managed-by-host`라는 공개 표식을 사용하지만, 이 값은 외부에서 사용할 수 있는 인증 키가 아닙니다. Studio는 원본의 영어 UI를 사용하며 Ned의 메뉴와 안내는 한국어로 제공합니다.

Studio는 별도 격리 창에서 열립니다. 같은 메뉴를 다시 누르면 열린 창으로 이동합니다. Studio 창만 닫아도 Ned와 지식 서비스는 계속 실행합니다. Ned 종료·설정 재시작이나 지식 서비스의 종료 때에는 Studio도 닫습니다. 개인 브라우저·Zed 프로필과 연결하지 않습니다.

이 창은 번들 화면과 허용한 로컬 지식 API만 사용합니다. 외부 URL·팝업·Node 접근·서버 관리/인증 변경·임의 MCP 연결은 허용하지 않습니다. Studio의 원본 UI에 이런 메뉴가 보이더라도 Ned에서 지원하는 연결과 구분합니다. 모델 연결 정보는 Ned의 중앙 JSON에서 변경합니다. 자료의 별도 내보내기와 이관은 [개인 지식 이관 안내](openviking-personal-migration.md)를 사용하세요.

## 0.3.9 화면 진단

로컬 페이지 로드만으로 성공으로 처리하지 않고 실제 앱 DOM 표시를 확인합니다.
빈 화면이 15초간 유지되면 진단 코드와 다시 불러오기 버튼을 표시합니다. 이는 UI 준비
확인 시간이며 모델 생성의 대기 제한과는 관계없습니다. 창을 닫거나 Ned를 종료하면
검사 타이머와 임시 세션도 정리합니다.

`%APPDATA%\Ned\openviking\studio-status.json`에는 `STUDIO_AUTH`, `STUDIO_RESOURCE`,
`STUDIO_POLICY`, `STUDIO_RENDER_TIMEOUT`, `STUDIO_RENDERER_EXIT` 같은 코드와
필요한 HTTP 상태만 남깁니다. 페이지 로그 전문·토큰·개인 내용은 기록하지 않습니다.
CSP는 고정 번들의 UUID 호환 코드 해시만 추가 허용합니다. 실제 Windows 흰 화면의
모든 원인을 확정한 것은 아니며 코드를 통해 인증·자료·정책·렌더러 문제를 구분합니다.
