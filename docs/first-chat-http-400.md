# Ned 0.3.7 첫 대화 HTTP 400 확인 패치

Ned와 개인 Zed를 완전히 종료한 뒤 `APPLY_FIX.cmd`를 실행합니다. `applied` 또는 `already-applied`, `EXIT_CODE=0`을 확인하고 Ned를 다시 켭니다. 복구는 같은 폴더의 `ROLLBACK_FIX.cmd`입니다. 원본 0.3.7 설치본의 호스트 해시를 확인하며 다른 빌드에는 적용하지 않습니다. 설정·대화·지식·편집기 배치와 OpenViking 0.5.4 런타임은 바꾸지 않습니다.

자동 스킬 지침을 기존 첫 system 메시지에 합칩니다. 첫 system 메시지를 하나만 허용하는 OpenAI 호환 템플릿이 두 번째 system 메시지를 거절하는 경우를 수정합니다. 스킬 지침·호스트 정책·사용자 메시지·도구·모델 옵션을 유지합니다. 실제 사내 서버의 이번 400이 같은 원인이라고 단정하지는 않습니다.

서버가 다시 HTTP 오류를 반환하면 원문을 저장하거나 화면에 복사하지 않고, 대기열·문맥/출력 한도·메시지/도구 형식·미지원 옵션 등의 고정 분류로 기록합니다. `%APPDATA%\Ned\model-gateway-status.json`에 `diagnosticRevision: 1`, `httpError`, `requestShape`, `skillRegistration`, `knowledgeRequests`가 추가됩니다. 키·URL·모델 ID·대화·코드·서버 오류 원문은 기록하지 않습니다. `unclassified`이면 원인을 확정하지 못한 상태입니다.

패치 후 같은 작업에서 대화 성공 여부를 확인합니다. 다시 실패하면 새 상태 JSON만 공유하면 됩니다. 기존 상태 파일은 마지막 실패 기록이므로 시각도 함께 확인하세요. 임의의 모델 생성 제한 시간이나 HTTP 400 자동 재시도는 추가하지 않습니다. 이미 거절된 오류 응답의 분류에는 최대 2초·64 KiB만 사용합니다.

확인한 기존 기록은 50,400바이트의 대화 요청이 28ms 만에 400으로 거절된 것입니다. OpenViking 로그는 약 5시간 뒤의 embedding 성공 기록이어서 동시 요청을 입증하지 않습니다. 스킬 등록 완료 전후 차이는 재현 조건으로 확인하되, 등록 때문이라는 결론은 새 진단이나 서버 근거가 필요합니다.
