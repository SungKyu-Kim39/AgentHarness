# Ned 0.3.0 검증 상태

상태: Zed 기반 전환 검증 후보. Windows 실제 수용은 미완료이며 1.0 완료를 의미하지 않는다.

## 확인한 범위

- Linux Node 24 환경에서 실행기·ACP 번들 빌드와 TypeScript 검사를 수행하였다.
- 실제 고정 OpenCode 2.2.6 엔진과 합성 OpenAI 호환 서버를 연결하여 ACP 초기화, 모델 목록, 새 세션, 대화, 승인 후 실제 파일 수정, 저장하지 않은 버퍼가 있을 때 수정 차단을 확인하였다.
- 외부 MCP 주입 거절과 모델 키가 ACP 이벤트에 포함되지 않음을 확인하였다.
- 기존 모델 선택·thinking 변형·요청 범위 자동 승인과 엔진 수명 정책 회귀 검사를 수행하였다.
- 이관은 합성 암호화 파일·종료된 DB 파일로 원본 보존·기존 대상 보존·실행 중 차단·링크 차단을 확인하였다. 실제 Windows DPAPI/DB 이관을 대체하지 않는다.
- VS 도구는 구성 탐색·승인 거절·승인 후 변경·범위 밖 참조·인자 주입 거절을 합성 파일로 검사하였다. Windows의 실제 MSBuild 실행·성공·취소를 확인한 것은 아니다.
- 새 PNG와 다중 해상도 ICO를 생성하고 제품 자산·빌드 경로에 연결하였다.

## 실행 기록

2026-11-12, Linux x64, Node 24.22.1, 고정 OpenCode 2.2.6 및 합성 OpenAI 호환 endpoint에서 `npm run build`, `npm run typecheck`, `npm run skills:verify`, `npm test`를 실행하였다. 전체 80개 검사 통과, 실패·생략 0개, 소요 약 448초였다. 모델 대기 검사는 188초 동안 기존 180초 경계를 넘어 유지한 뒤 사용자 중지를 확인하였다. 실제 사내 endpoint나 실제 Windows 결과가 아니다. 이후 승인·ACP 변경은 관련 연동 검사를 다시 수행한다.

ACP 번들이 읽는 원본 192개 파일을 고정 OpenCode 소스 아카이브와 대조하고 `ned-acp-lock.json`으로 기록한다. Zed는 `ned-runtime-lock.json`의 원본 바이너리/소스 크기와 SHA-256을 검사한다.

## 남은 확인

실제 Zed Windows 화면, 설치 EXE·바로가기·실행 아이콘, 처음 설정·재가져오기·기존 데이터 이관, 일반 사용자 ACL·복호화 실패, 실제 사내 모델 대기열·압축, OpenViking 스킬 등록·검색, C++ SDK와 VS 빌드·자식 종료, 개인 Zed 동시 실행, 최초 실행부터 종료까지 DNS/TCP 관찰이 필요하다.

원래 Zed 설정·확장 기능이 프로젝트 설정과 상호작용하는 경로도 Windows 오프라인 수용에서 확인한다. 프록시와 설정을 적용했다는 사실만으로 완전한 네트워크 차단을 입증하지 않는다. 설치 파일의 바이트·해시·소스 커밋·검증 명령은 실제 생성 후 함께 기록한다.

## 설치기와 반입 파일

빌드 소스는 `fd4ad45ec00a8831fc951dab5c27365cc1eb7015`이다. `npm run package:win`으로 설치기를 생성하고 7-Zip으로 실제 EXE를 다시 풀어 검사하였다. 설치기 파일 94,216개·디렉터리 8,739개가 ASCII이며, OpenViking 63,069개·MCP 21,031개·REA 9,019개·스킬 259개/34종의 고정 파일 해시를 대조하였다. 새 실행기의 제품명 Ned와 7개 크기의 아이콘 이미지 일치, ACP용 Electron Node 실행 모드도 확인하였다.

`npm run bundle:offline` 결과 TGZ는 1,128,796,546 bytes, SHA-256 `674ea4dc96640282ea21f5dee6586a6ff9167aadb15878c07fa2bfdc9330f711`이다. 내부 EXE는 1,132,157,259 bytes, SHA-256 `78c6d5e9190ea2175e8e6542ca235b5afa6ecc6dffdec224e0bc4a336fb8b10b`이다. TGZ의 21개 항목과 내부 소스 묶음의 519개 항목을 검사하고 EXE를 스트리밍 해시하여 동일성을 확인하였다. [다운로드·manifest](../downloads/README.md)에 근거를 함께 제공한다.

이 검사는 Linux에서의 파일·패키지 검증이다. 실제 Windows에서 아이콘이 표시되고 프로그램이 정상 작동했다는 판정은 포함하지 않는다.
