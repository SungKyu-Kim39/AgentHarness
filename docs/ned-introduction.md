# Ned: 자연어로 요청하면 적정한 도구와 스킬을 자동으로 연결하는 사내 AI 개발 환경

사내 Qwen 모델에 Zed를 연결하면 코드에 관해 질문하고 수정안을 받을 수 있습니다. 여기에 코드 분석, 작업 계획, 문서 변환, 지식 검색을 더하려면 도구마다 런타임을 설치하고 설정을 맞춰야 합니다. 폐쇄망에서는 빠뜨린 구성 요소 하나를 다시 반입하는 데도 시간이 듭니다.

Ned는 이 준비 과정을 줄이기 위해 만든 Windows용 바이브 코딩 환경입니다. 이 문서는 **Ned 0.4.1** 기본 배포 구성을 기준으로 설명합니다. Zed, 전용 OpenCode 엔진, 개발 도구와 기본 스킬 79개, Workspace Tools(HWP/HWPX·Office·AST·보안 감사·다이어그램), OpenViking 개인화 지식 저장소를 하나의 설치 묶음으로 제공합니다. 도구를 직접 구성하기 어려운 직원도 사내 모델 정보만 설정하면, 평소처럼 자연어로 요청해 상황에 맞는 스킬과 도구가 자동으로 연결되는 환경에서 바로 작업을 시작할 수 있습니다.

처음 사용하는 분을 위한 [상세 사용 안내서](ned-user-guide.md)에는 주요 도구의 설명, 스킬 79종의 용도와 대화에 옮겨 쓸 수 있는 요청 예시를 담았습니다. 자연어 의도 분석과 자동 도구 연결 구조를 외부 링크 없는 한 편으로 공유하고 싶다면 [자연어 자동 도구 연결 소개·안내·상세 가이드](ned-auto-routing-guide.md)를 참고하세요.

## 편집기에서 조사와 수정을 이어갑니다

코드를 수정할 때는 새 함수를 작성하는 일보다 기존 동작을 파악하는 데 더 많은 시간이 들기도 합니다. 호출하는 곳을 찾고, 플랫폼별 차이를 확인하고, 변경 이유를 문서로 남겨야 하기 때문입니다.

Ned에서는 Zed로 코드를 읽고 직접 편집하면서 AI에 조사를 맡길 수 있습니다. **Ctrl+Shift+A**로 대화를 열고 작업할 범위와 유지할 조건을 설명하면, Ned가 요청의 의도와 문맥을 분석해 관련 스킬 지침·전문 도구·개인 기억을 자동으로 붙이고, 에이전트가 프로젝트 파일과 도구 결과를 참고해 답변하거나 수정안을 만듭니다.

예를 들어 다음과 같이 요청할 수 있습니다.

> 이 프로젝트의 주요 모듈과 진입점을 조사하고, 처음 참여하는 개발자가 읽을 수 있는 구조 설명서를 작성하라.

> 이 함수에서 오류가 발생할 수 있는 경로를 조사하고, 기존 동작을 유지하는 수정안을 제시하라.

> 이 모듈의 Windows 이식 방안을 검토하라. 기존 VxWorks 지원을 유지해야 하며, 플랫폼에 종속된 부분과 추가 확인이 필요한 사항을 구분하라.

사용자는 설명과 함께 실제 도구 호출 결과를 확인하고 작업 방향을 조정할 수 있습니다. 직접 편집한 코드는 일반 IDE처럼 저장합니다. AI가 기존 파일을 고칠 때는 `patch_file`로 필요한 구간만 부분 편집하고, 대상 내용과 저장하지 않은 편집 내용을 대조해 기존 변경을 덮어쓰지 않도록 합니다.

Ned에서 말하는 바이브 코딩은 자연어로 목적을 설명하고, 코드와 실행 결과를 보며 구현을 구체화하는 방식입니다. 요청할 때 대상 파일, 유지할 동작, 완료 기준을 함께 알려 주면 검토할 범위가 분명해집니다.

## 설치와 모델 설정

Ned는 Windows 10·11 x64용으로 배포합니다. 반입할 파일은 TGZ 하나이며, 압축을 풀면 설치 EXE와 설정 예제, 안내 문서, 대응 소스를 확인할 수 있습니다.

1. TGZ를 새 폴더에 풉니다.
2. EXE로 설치합니다. 설치 위치를 바꿀 수 있고, 폴더가 없으면 자동으로 만듭니다.
3. 최초 준비 파일인 `%APPDATA%\Ned\config-import.json`에 사내 모델 정보를 입력합니다. 설치 전에 EXE 옆 `agent-config.json`을 작성했다면 그 내용이 복사됩니다.
4. Ned를 실행하고 프로젝트와 모델을 선택합니다.

직원 PC에서 외부 인터넷으로 런타임을 추가 설치하는 절차는 없습니다. 사내 PyPI 미러가 라우팅된 환경이라면 프로젝트별 `.venv`에서 필요한 Python 패키지를 관리할 수 있습니다. 모델 가중치도 포함하지 않으며, 답변 생성과 임베딩에는 설정한 사내 API를 사용합니다.

여러 LLM의 주소·키·모델 ID를 등록해 대화에서 선택할 수 있습니다. 컨텍스트와 출력 토큰 한도, thinking 옵션도 서버가 지원하는 범위에 맞게 설정합니다. 임베딩 모델은 별도로 한 개를 지정합니다. 사내 서버의 대기열이 길어도 기다릴 수 있도록 모델 응답에는 기본 시간 제한을 두지 않았습니다.

API 키는 Windows 사용자 보호 기능으로 암호화해 저장합니다. 이후 설정을 바꿀 때는 **Ned → 설정 JSON 가져와 적용 (자동 재시작)**을 사용합니다. 편집기의 저장 확인과 서비스 종료를 마치면 새 설정으로 다시 실행합니다. 업데이트할 때는 모델 설정, 권한 모드, 대화, 지식, 사용자 글로벌 스킬, 편집기 글꼴과 패널 배치를 보존합니다.

## 각 구성 요소가 맡는 일

| 구성 | 담당하는 일 |
| --- | --- |
| Zed | 파일 탐색, 코드 직접 편집·저장, 대화와 패널 화면 |
| OpenCode | 에이전트 세션과 모델 요청, 작업에 필요한 도구 호출 |
| Ned 호스트 | 설정과 키 보관, 프로젝트 접근, 권한 관리, 자연어 자동 라우팅, Shadow Git 체크포인트·worktree·도구·서비스 관리 |
| 기본 스킬 79개 | 계획, Spec-Driven, 디버깅, 리뷰, UI, Astryx, EGM, HWP/Office 문서, 다이어그램, 데이터 앱 등에 필요한 작업 지침 |
| Aegis·Conductor | 개발 방법론과 기존 트랙의 계획·진행·검증 기록 활용 |
| Serena·clangd | C/C++ 심볼의 정의·참조와 코드 구조 조사 |
| Graphify·REA·Ghidra | 소스의 AST 구조 분석과 지원 산출물·바이너리의 오프라인 정적 리버싱 |
| Workspace Tools | 다국어 `ast-grep-py` 검색·치환, 정적 보안 감사(`bandit`), HWP/HWPX·MS Office 양방향 생성, PDF 표 추출, `.drawio`/Mermaid 다이어그램, OpenAPI 로컬 Mock·계약 검증 |
| 개발 MCP 6종 | Serena, Git, Playwright, MarkItDown, Chrome DevTools, DuckDB Local 연결 |
| agent-desktop | 로컬 GUI 앱 실행, 지정한 창의 접근성 정보 확인과 지원 동작 수행 |
| OpenViking | 프로젝트 문서 색인, 명시적 지식 노트, 백그라운드 VLM 기반 개인화 대화 기억 자동 추출·회상 |

스킬은 작업 방법을 담은 문서이고, MCP·호스트 도구는 실제 기능을 호출하는 실행 계층입니다. Ned는 별도 모델 호출 없이 요청과 최근 대화 문맥에 맞는 스킬 지침(새로 추가한 사용자 글로벌·프로젝트 `.ned/skills` 포함)을 자동으로 불러오고, 데스크톱·리버싱처럼 특수한 도구는 관련 요청이나 슬래시 스킬(`/skill-...`)·하위 에이전트 위임이 있을 때만 조건부로 노출해 오호출을 줄입니다.

도구는 Ned가 검토한 기능만 노출합니다. 예를 들어 문서 도구는 지원 파일을 텍스트로 변환하고, 데이터 도구는 선택한 로컬 파일을 조회합니다. 브라우저 도구는 허용한 로컬 개발 페이지를 관찰합니다. 스킬을 읽었다는 사실과 도구를 실행해 결과를 확인했다는 사실은 작업 기록에서 구분합니다.

## 반복 승인을 조절할 수 있습니다

권한은 대화 입력창이나 알림 영역에서 선택합니다.

| 모드 | 사용 방식 |
| --- | --- |
| 승인 요청 | 파일 수정·삭제, 외부 읽기, 셸 명령, 빌드, 지식 저장·색인, 데스크톱 작업을 실행하기 전에 확인합니다. |
| 프로젝트 파일 자동 승인 | 선택한 프로젝트의 파일 생성·수정·삭제를 이어서 허용하고, 다른 종류의 작업은 확인합니다. |
| 전체 권한 | Ned가 지원하는 일반 작업의 반복 승인창을 생략합니다. 단, 중첩 셸·동적 평가·외부 전송·시스템 경로 삭제 등 고위험 셸 명령은 계속 명시적으로 확인하며 외부 파일 쓰기와 개인 키 읽기는 차단합니다. |

선택은 재시작과 업데이트 후에도 유지됩니다. 모든 모드에서 파일 경로, 외부 변경 충돌, 저장하지 않은 편집 내용과 중지 상태를 검사합니다. 기존 VxWorks 지원을 유지할지처럼 제품 방향을 정하는 질문은 사용자의 판단이 필요합니다.

VS2017/2019/2022가 설치되어 있으면 MSBuild와 솔루션 구성을 조사한 뒤 지원하는 빌드를 실행할 수 있습니다. 필요한 컴파일러·SDK와 프로젝트 의존성은 미리 준비해야 합니다. C/C++ 의미 분석도 `compile_commands.json`, include 경로와 매크로가 갖춰져 있을 때 더 정확한 결과를 얻을 수 있습니다.

Python 프로젝트는 PC에 설치된 Conda 환경을 사용합니다. 처음 실행할 때 환경 목록에서 사용할 환경을 고르면 같은 프로젝트에서는 계속 그 환경을 사용합니다. 선택은 로컬에 보존하고 OpenViking에도 기록합니다. 기존 패키지로 실행·pytest·wheel·PyInstaller 작업을 수행하며 필요한 패키지를 자동 설치하지 않습니다. [Conda 사용 안내](python-conda.md)에 요청 예시와 환경 변경 방법을 정리했습니다.

agent-desktop은 선택한 권한 모드에 따라 앱을 실행하고 지정한 창을 조작합니다. 실제로 읽은 접근성 정보와 동작 결과를 사용하며, 전역 키·좌표 입력이나 클립보드, 관리형 편집기·승인창 조작은 제공하지 않습니다. 지원 범위는 Windows 접근성 정보와 실행 권한의 영향을 받습니다.

## 개발 지식과 개인화 대화 기억을 활용하는 방법

코드에는 설계 의도와 운영상의 제약이 모두 담겨 있지 않습니다. 인터페이스 문서, 장애 대응 기록, 이전에 정한 개발 규칙과 개인 작업 선호도도 필요합니다. OpenViking 0.5.5는 Ned와 함께 백그라운드로 시작하고 종료하며, 데이터는 사용자 폴더에 보관합니다.

- **프로젝트 문서 색인과 명시적 노트**: 사용자가 선택한 문서를 프로젝트 지식에 색인하거나, 특정 규칙·결정을 프로젝트/개인 노트로 저장해 다시 검색할 수 있습니다.
- **개인화 대화 기억 자동 추출·회상**: OpenViking이 활성화되면 Ned 주 대화에서 기본 6턴마다(또는 세션 전환·종료 시) 백그라운드 VLM이 재사용할 개인 기억을 추출하고 다음 요청에서 자동 회상합니다.
- **프라이버시·시크릿 보호와 투명한 제어**: 회상과 저장 양쪽에서 API 키·JWT·PEM 개인키·비밀번호 등을 마스킹하며, `"이건 기억하지 마"`(턴 제외)나 `"이 세션은 기억하지 마"`(세션 제외)로 바로 제외할 수 있습니다. `openViking.memory` 설정으로 켜기·끄기와 주기를 조정하고, Windows 알림 영역의 트레이 메뉴에서 현재 상태를 실시간으로 확인하며 **OpenViking Studio 열기**로 저장된 기억을 직접 조회·삭제할 수 있습니다. 프로젝트 전체 파일이나 공용 저장소에 임의로 업로드하지는 않습니다.

프로젝트 파일 삭제에는 `delete_file`을 사용하며, `patch_file`·`propose_edit`와 같은 권한·미저장 버퍼 검사와 복구 스냅샷을 적용합니다. 현재 삭제 범위는 2 MiB 이하 UTF-8 텍스트 파일 하나입니다.

## 익숙한 작업에서 시작하세요

처음에는 결과를 직접 판단할 수 있는 일을 맡기는 것이 좋습니다. 익숙한 함수의 오류 처리 검토, 모듈 구조 설명, README 보완처럼 범위가 작은 작업이 적합합니다.

> 통신 모듈의 오류 처리를 검토하라. 공개 인터페이스와 정상 처리 동작은 유지하라. 먼저 관련 코드를 조사한 뒤 수정안을 제시하고, 별도로 실행해야 할 테스트 항목을 정리하라.

이런 작업에서는 AI가 관련 파일을 찾아 정리하는 시간을 줄이고, 개발자는 수정 근거와 영향에 집중할 수 있습니다. 신규 담당자에게는 코드 탐색의 출발점이 되고, 기존 담당자에게는 조사 내용을 설계 설명이나 인계 문서로 남기는 데 도움이 됩니다. 로컬 웹 화면의 접근성·콘솔 오류 확인과 데이터 조회에도 활용할 수 있습니다.

효과는 모델 성능과 프로젝트의 준비 상태에 따라 달라집니다. 제안한 코드는 기존 리뷰·빌드·테스트 절차에서 확인해야 합니다. Windows Server 설치·로딩 검사와 실제 직원 PC의 Windows 10·11 GUI·사내 모델 전체 검증도 구분하고 있습니다.
