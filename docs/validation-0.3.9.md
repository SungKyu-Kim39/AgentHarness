# Ned 0.3.9 구현 검증

검증일: 2026-11-17. Linux 개발 환경에서 수행한 소스 변경 검사입니다.
현재 공개 배포는 0.3.8 rebuild1이며, 0.3.9 EXE·TGZ·릴리스는 생성하거나 게시하지 않았습니다.

## 수행한 검사

- `npm run typecheck`: TypeScript 검사.
- `npm run skills:verify`: 74종의 문서·라이선스·고정 manifest 해시 검사.
- `npm run build`: 준비된 스킬 74종 생성, 고정 OpenCode 2.2.6 ACP 번들 및 Ned 호스트 빌드,
  실제 배포 CommonJS 모듈을 로드하는 호스트 smoke 검사.
- `npm test`: 전체 회귀 결과는 아래 최종 결과에 기록합니다. 제외는 누락된 고정 실행 파일과
  Windows·과거 SDK 등 환경 조건에 따른 것이며 통과로 집계하지 않습니다.
- 실제 Linux OpenViking 0.5.5: 사전 준비한 스킬을 인증된 SDK API로 읽었습니다.
  설치 단계의 스킬 모델 호출 0건, 로컬 스킬의 재시작 재사용과 추가 모델 호출 0건을
  확인하고 실제 프로젝트 색인·검색의 범위를 검사했습니다. SDK의 첫 계정 접근 시
  기본 폴더 임베딩이 발생하므로 이 큐를 완료한 뒤 재시작을 비교했습니다.
- 실제 0.5.5 Studio 번들: 격리 Chromium에서 앱 표시, 인증된 상태 조회와 Filesystem
  이동, 외부 요청 차단, 페이지 오류 없음, 저장소·페이지의 실행 토큰 미노출을 확인했습니다.
  Electron 창·트레이·Windows GUI 검사는 아닙니다.
- SQLite: WAL의 확정 행, JSON·zstd, 원본 보존, sandbox 승인·모델 초기화, 중복·ID 충돌,
  기존 스키마의 메타데이터 열, 미지원 형식 제외, 하드 링크와 백업 경로 링크 차단을 확인했습니다.
- 합성 모델/HTTP: native 모델별 선택과 인증, 프록시 절대 URL·일반 요청 첫 메시지,
  외부/다른 포트/다른 경로 차단, 잘못된 토큰, 취소 후 연결 정리를 확인했습니다.
- 호스트 fixture: Goldfish의 새 세션·고정 검토자와 메모리·수정·재위임 차단,
  CMD 선택 유지와 두 셸의 독립 작업, Studio의 빈 화면 진단→재시도→표시를 검사했습니다.
- 스킬 fixture: 준비 묶음 변조 차단, SDK YAML 직렬화 차이, 사용자 수정과 추가 자료 보존,
  갱신 전 원본 백업과 교체 중단 복구를 검사했습니다.
- 공식 Zed 1.28.1 대응 소스의 SHA-256
  `2baab0ae5fdbbdd64cf69afbc4fd3f4427dc86b9a8a4dfd2335a949097741226`을 확인한 뒤
  0.3.9 메뉴/About 소스 패치를 적용했습니다. 두 고정 원본 파일의 사전 해시가 일치했습니다.
  Rust Windows 실행 파일 컴파일·GUI 표시는 수행하지 않았습니다.
- workflow YAML 문법과 `git diff --check`를 검사했습니다. 새 파일의 문서 링크와 EGM
  출처·라이선스·고정 커밋/파일 해시도 확인했습니다.

## 최종 결과

전체 회귀 232건 중 **202건 통과·30건 제외·실패 0건**입니다. 마지막 스킬 소유권·색인 상태
표시 보완 뒤 실제 준비 묶음을 사용하는 SDK·스킬·대화 대상 검사 8건도 모두 통과했습니다.
그 앞의 설정·native 통신·대화·터미널·Studio 대상 검사 18건과 별도 실제 Studio 표시 1건도
통과했습니다. 타입·74종 스킬·호스트/ACP 빌드와 호스트 모듈 smoke를 통과했습니다.

전체 실행에서 기존 Conda 지식 검사 1건이 SDK 폴더의 비동기 임베딩과 모델 호출 수 비교를
겹쳐 세어 실패했습니다. SDK 처리 큐를 완료한 뒤 재사용을 비교하도록 검사 시점을 바로잡고
재실행해 통과했습니다. 제품의 색인 동작을 줄여 테스트를 맞추지 않았습니다.

EGM lock의 95개 파일 해시를 대조했고, 공식 Zed 대응 소스의 0.3.9 패치를 적용했습니다.
`git diff --check`, 새 문서 링크, workflow YAML 문법과 배포 스크립트 구문도 통과했습니다.
요구사항과 코드·권한 경계의 두 관점을 동일 에이전트가 순차 검토했습니다. 독립 리뷰나
Windows 수용으로 표현하지 않습니다.

## 배포 준비 중 추가 확인

구버전 SDK 0.5.4와 현재 SDK 0.5.5를 Linux에서 실행해 계정·프로젝트·개인 자료와 두 기본
스킬의 이름 이관, 원본 백업, 변경분 적용과 재시작 시 추가 색인 없음까지 확인했습니다.
이관 중 SDK가 검증한 파일 해시를 로컬 준비 절차로 전달해 사용자 수정본과 구별합니다.
Windows용으로 번들한 검사도 Linux에서 50건 중 42건 통과·8건 환경별 제외·실패 0건을
확인했습니다. 이 결과는 Windows에서 실행한 결과와 구별합니다.

최종 Git 신뢰 설정은 번들 Git의 경로와 Zed가 감시하는 Ned 전용 Git 설정 파일을
연결합니다. Linux Git으로 소유권 검사를 강제해 선택 경로만 신뢰되는 동작과 다른 저장소의
소유권 검사, 외부 전송 제한을 확인했습니다. Windows 설치 검사에서는 번들 Git의 실제
실행 경로, 공백이 있는 저장소 경로와 재시작 후 설정 유지도 검사합니다.

## 배포 전 남은 확인

0.3.9용 Windows 소스 빌드 편집기·대응 소스·버전별 build 메타데이터가 필요합니다.
`editor-source-build` 작업은 현재 package 버전으로 빌드해 검토용 artifact로 올립니다.
이를 검토 후 `downloads/editor`에 반입해야 합니다. 기존 build.json과 0.3.8 rebuild1
컴포넌트를 0.3.9 편집기로 인정하거나 덮어쓰지 않습니다.

기존 `release-runtime-lock.json`은 이전 버전의 검증 자료입니다. 정확한 LFS 원본을 준비하고
0.3.9 `release-prepare`로 생성한 manifest·라이선스·전체 설치 payload 감사가 필요합니다.
설치 자료에는 준비 스킬, EGM/Studio lock, YAML ISC 원문과 새 사용 안내를 포함합니다.
해시를 추정하여 lock을 바꾸거나 과거 수용 결과를 새 버전에 복사하지 않았습니다.

실제 Win10/11 첫 설치·0.3.7/0.3.8 업데이트, 사용자 수정 스킬·대화·설정 보존,
Zed의 설정 읽기와 첫 메시지/스트리밍/중지, 개인 원본 DB 목록·재개, PowerShell/CMD,
Studio 창 재시도·종료, 실제 사내 모델과 외부 DNS/TCP 차단을 확인해야 합니다.
Goldfish 실제 엔진의 모델 입력 격리와 검토 품질·결과 통합도 추가 수용 항목입니다.

사용자가 제보한 `Ned offline editor` 응답의 발생 위치는 확인했지만 해당 Windows PC의
실제 요청 형태와 사내 서버 첫 응답은 확보하지 못했습니다. 동일한 프록시 경로의 합성
검사가 실제 직원 PC 수용을 대신하지 않습니다. 시작·설치 성능의 Windows 전후 측정과
설치 압축 해제의 코어 사용량도 미측정이며 개선율·전체 코어 사용을 주장하지 않습니다.
