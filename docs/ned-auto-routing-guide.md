# Ned 소개·안내·상세 가이드: 자연어 요청을 분석해 적정한 도구와 스킬을 자동으로 연결하는 사내 AI 개발 환경

이 문서는 별도의 외부 링크나 다른 문서 참조 없이 한 편만으로 Ned 0.4.0의 핵심 가치, 동작 구조, 자동 도구·스킬 연결 방식, 실전 활용법과 안전 원칙을 모두 이해할 수 있도록 작성한 독립 안내서입니다. 사내 위키, 메일, PDF 등으로 그대로 복사해 배포해도 깨지는 링크가 없습니다.

---

## 1. 소개: 왜 Ned인가

일반 편집기(Zed 등)에 사내 LLM 모델만 연결해도 코드에 대해 질문하거나 수정안을 받을 수는 있습니다. 하지만 실제 개발 업무에 들어가면 곧바로 한계에 부딪힙니다.

- C/C++ 함수의 정확한 정의와 참조를 찾으려면 언어 서버와 심볼 분석 도구를 따로 연결해야 합니다.
- PDF·Word·Excel·HWP/HWPX 사양서나 CSV 데이터를 읽고 결과 보고서를 만들려면 문서 변환·생성·데이터 조회 도구를 따로 구성해야 합니다.
- 기존 설계 결정이나 반복되는 오류 해결 경험을 다음 작업에 활용하려면 지식 저장소와 임베딩 파이프라인을 별도로 운영해야 합니다.
- 디버깅, 대규모 리팩터링, 코드 리뷰, UI 개선, 한국어 문서 윤문처럼 작업 유형마다 에이전트에게 매번 긴 절차와 주의사항을 반복해서 설명해야 합니다.
- 폐쇄망 PC에서는 직원마다 npm이나 pip로 도구를 설치하고 설정을 맞추는 일 자체가 큰 부담입니다.

Ned는 Windows 10·11 x64 폐쇄망 환경을 위해 **Zed 편집기 + 전용 OpenCode 에이전트 엔진 + 40여 종의 검증된 로컬 개발·분석 도구(호스트·MCP·Workspace Tools) + 기본 스킬 79개 + OpenViking 개인화 지식 저장소**를 하나의 설치본으로 묶은 통합 개발 환경입니다.

그중에서도 Ned의 가장 큰 차별점은 **사용자가 도구 이름이나 스킬 목록을 외울 필요 없이 평소처럼 자연어로 요청하면, Ned가 요청의 의도와 작업 문맥을 분석해 필요한 스킬 지침·전문 도구·과거 기억을 자동으로 붙여 준다는 점**입니다.

## 2. 핵심 동작 원리: 자연어 한 문장이 실행으로 이어지는 5단계

사용자가 Zed에서 `Ctrl+Shift+A`로 Ned 대화를 열고 자연어로 작업을 요청하면, 모델이 답변을 생성하고 도구를 실행하기까지 화면 뒤에서 다음 5단계가 자동으로 작동합니다.

```text
[사용자 자연어 요청]
        │
        ▼
(1) 자동 스킬 라우팅 (ModelGateway · automaticSkillContext)
    - 별도 LLM 호출 없이 요청 의도·최근 대화·파일 확장자를 로컬에서 즉시 분석
    - 기본 스킬 79개 + 재시작 없이 실시간 탐색한 사용자 글로벌·프로젝트(.ned/skills) 스킬 중 관련 지침 최대 3개 자동 주입
        │
        ▼
(2) 전문 도구 조건부 노출 및 호스트 이중 검증 (hideUnrequestedTools · toolRequested)
    - 일반 코딩 시 데스크톱 GUI·리버싱·문서 생성·다이어그램·OpenAPI·worktree 도구를 숨겨 오호출 방지
    - 관련 요청·슬래시 스킬·위임된 하위 에이전트 문맥 시 자동 활성화하고 후속 턴 유지
        │
        ▼
(3) 개인화 대화 기억 자동 회상 (SessionMemoryManager · OpenViking)
    - 요청 질의어에서 민감 정보(토큰·비밀번호·개인키 등)를 먼저 마스킹
    - 과거 대화에서 백그라운드 VLM으로 추출한 관련 기억·프로필만 자동 첨부
        │
        ▼
(4) 에이전트 도구 선택 및 조합 (전용 OpenCode 엔진)
    - 주입된 스킬 지침·기억·도구 명세를 바탕으로 탐색 → 분석 → 수정 → 검증 순서 실행
        │
        ▼
(5) 호스트 안전 가드 및 권한 집행 (Ned HostTools)
    - 사용자 선택 권한 모드(승인 요청 / 파일 자동 승인 / 전체 권한) 적용
    - 프로젝트 경로 격리, 미저장 버퍼 가드, 복구 스냅샷·Shadow Git 체크포인트, 고위험 셸 가드 강제
```

### 단계별로 중요한 설계 특징

1. **추가 대기 시간이 없는 로컬 자동 라우팅**
   사내 모델은 동시 사용자가 몰릴 때 대기열이 길어질 수 있습니다. Ned는 스킬을 고르기 위해 별도의 모델 호출을 추가로 발생시키지 않습니다. 로컬 호스트 게이트웨이에서 요청 본문과 최근 대화 문맥을 즉시 분석해, 본 요청 한 번에 필요한 스킬 지침을 함께 실어 보냅니다. 앱을 재시작하지 않아도 새로 추가한 글로벌 스킬과 현재 프로젝트의 `.ned/skills` 지침까지 실시간으로 탐색해 반영합니다.
2. **도구 과다 노출 방지와 문맥 유지**
   모든 도구를 매번 모델에 한꺼번에 노출하면 일반 코드 수정 요청에서도 엉뚱한 GUI 조작이나 리버싱·문서 생성 도구를 호출할 위험이 커집니다. Ned는 파일·Git·빌드·심볼·문서 읽기·데이터·지식·체크포인트·AST 같은 핵심 개발 도구는 상시 연결하되, Windows GUI 조작(`desktop_*`), 바이너리 정적 리버싱(`rea_*`), 문서 쓰기(`document_write`), 다이어그램(`diagram_*`), OpenAPI(`api_*`), `worktree_sandbox`처럼 특수 목적이 뚜렷한 도구군은 관련 자연어 요청이나 슬래시 스킬이 있을 때만 자동으로 열어 줍니다. 직전 턴 문맥은 물론 위임된 하위 에이전트의 작업 지시 문맥도 일관되게 유지해 "응, 공학용으로 바꿔서 계속해" 같은 짧은 후속 지시나 하위 조사 작업에서도 도구가 끊기지 않습니다.
3. **쓰면 쓸수록 똑똑해지는 개인화 RAG 기억**
   OpenViking이 활성화된 상태에서 Ned 주 대화를 진행하면, 일정 턴(기본 6턴)마다 또는 세션 전환·종료 시 백그라운드 VLM이 대화에서 재사용할 만한 선호·규칙·해결 이력을 자동 추출해 저장합니다. 다음 작업에서 비슷한 주제로 질문하면 관련 기억을 자동으로 회상해 맥락에 붙여 줍니다.
4. **지침과 실행 권한의 엄격한 분리**
   자동으로 붙는 스킬 문서나 과거 기억은 어디까지나 작업 절차와 참고 자료입니다. 어떤 스킬 문구나 저장된 기억도 파일 수정·명령 실행 권한을 임의로 부여하거나 호스트의 안전 검사를 건너뛸 수 없습니다.

## 3. 상세 안내: 이렇게 말하면 Ned가 이런 스킬과 도구를 자동으로 붙입니다

사용자가 도구 이름이나 영문 명령어를 외울 필요는 없습니다. 아래 표는 실제 업무에서 자주 쓰는 자연어 요청 유형에 따라 Ned가 어떤 스킬 지침과 도구를 자동으로 연결해 활용하는지 정리한 상세 매핑입니다.

### 3.1 코드 탐색·부분 수정·안전 삭제

- **자연어 요청 예시**: "이 함수에서 빈 경로를 받을 때 오류 메시지를 명확하게 고쳐줘", "사용하지 않는 구 설정 파일을 지워줘"
- **자동 연결 도구**: `list_files`, `read_file`, `search_text`, `patch_file`, `propose_edit`, `delete_file`
- **동작 특징**:
  - 기존 파일의 일부를 고칠 때는 파일 전체를 덮어쓰는 대신 `patch_file`로 필요한 구간만 부분 편집해 수정 속도와 정확도를 높입니다.
  - 수정·삭제 직전에 Zed 편집기의 미저장 버퍼와 디스크 해시를 대조해 사용자가 저장하지 않은 편집 내용을 덮어쓰지 않도록 막습니다.
  - 모든 수정·삭제 전 원본은 `%APPDATA%\Ned\snapshots`에 스냅샷으로 보존하며, `.git`·`.zed`·`.ned`·`.vscode`·`opencode.json` 등 실행·내부 관리 경로의 임의 수정은 차단합니다.

### 3.2 오류 분석·버그 수정·디버깅

- **자연어 요청 예시**: "실행하면 가끔 크래시 나는 원인을 찾아 고쳐줘", "이 테스트가 왜 실패하는지 추적해줘"
- **자동 부착 스킬**: `diagnosing-bugs`, `systematic-debugging`
- **자동 연결 도구**: `read_file`, `search_text`, `git_inspect`, `semantic_symbols`, `run_python` 또는 `run_terminal`, `patch_file`
- **동작 특징**: 증상만 보고 추측성 수정을 반복하지 않고, 재현 조건 확인 → 가설 검증 → 최소 수정 → 회귀 확인 순서로 진행하도록 지침을 자동으로 붙입니다.

### 3.3 C/C++ 의미 분석·대규모 이식·MSBuild 빌드

- **자연어 요청 예시**: "이 C++ 통신 모듈을 Windows로 이식할 영향 범위를 조사하고 VS2022로 빌드해줘. 기존 VxWorks 지원은 유지해야 해"
- **자동 부착 스킬**: `cpp-pro`, `cpp-coding-standards`, `cpp-testing`, `change-impact`, `writing-plans`
- **자동 연결 도구**: `semantic_symbols`(Serena + 번들 clangd), `graphify_analyze`(AST 구조 분석), `read_methodology`(Aegis/Conductor), `inspect_build`, `build_project`(VS2017/2019/2022 MSBuild)
- **동작 특징**: 단순 문자열 검색이 아니라 clangd 기반 정의·참조 조사와 AST 구조 분석을 결합하고, `compile_commands.json`이나 SDK 헤더 부재로 인한 분석 한계도 숨기지 않고 보고합니다.

### 3.4 코드 리뷰·설계 검토·병렬 하위 에이전트

- **자연어 요청 예시**: "이번 브랜치 변경분을 코드 리뷰해줘", "모듈 구조를 다시 설계하고 두 영역으로 나눠 조사해줘"
- **자동 부착 스킬**: `code-review`, `review`, `requesting-code-review`, `codebase-design`, `domain-modeling`, `qa-only`, `verification-before-completion`
- **자동 연결 도구**: `git_inspect`, `spawn_subagent`(조사 `research` · 지정 파일 구현 `worker` · 독립 검토 `goldfish`), `subagent_status`, `stop_subagent`
- **동작 특징**: 넓은 작업은 최대 2개의 실제 하위 에이전트에 조사나 겹치지 않는 파일 수정을 병렬 위임할 수 있으며, EGM Goldfish 검토자는 부모 대화와 기억을 차단한 백지 상태에서 독립 검토를 수행합니다.

### 3.5 Python·Conda·사내 PyPI `.venv` 및 패키지 API 역추적·데이터 앱 프리뷰

- **자연어 요청 예시**: "프로젝트 `.venv`를 만들고 사내 PyPI에서 `marimo`와 `pandas`를 설치해줘", "설치된 `pydantic` v2 API 시그니처를 확인해줘", "CSV 데이터를 보는 Streamlit 대시보드를 띄우고 확인해줘"
- **자동 부착 스킬**: `python-intranet-venv`, `data-app-builder`
- **자동 연결 도구**: `inspect_python`, `choose_python_environment`, `run_python`, `manage_python_venv`, `python_package_docs`, `python_app_preview`, `browser_check`
- **동작 특징**: 기존 Conda 환경 선택에 더해 프로젝트 전용 `.venv`에서 사내 PyPI 미러(PC 기본 `pip.ini`·라우팅 또는 중앙 JSON `python` 설정)를 통해 패키지를 안전하게 설치하고, 설치된 패키지의 실제 시그니처·docstring을 오프라인 AST/격리 검사로 역추적합니다. `marimo`·`Streamlit`·`FastAPI` 데이터 앱은 `127.0.0.1` 루프백 전용으로 실행하며, OpenViking 내부 Python이나 번들 런타임은 절대 오염시키지 않습니다.

### 3.6 Git 변경 확인·Shadow Git 턴 체크포인트·`git worktree` 병렬 샌드박스

- **자연어 요청 예시**: "변경된 파일 diff를 보여주고 내가 고친 두 파일만 커밋해줘", "방금 수정하기 전 체크포인트로 되돌려줘", "별도 worktree에서 리팩터링 실험을 돌려줘"
- **자동 연결 도구**: `git_inspect`, `git_stage`, `git_commit`, `project_checkpoint`, `worktree_sandbox`, `spawn_subagent(isolation="worktree")`
- **동작 특징**: 번들 Git을 사용하며 사용자가 지정한 파일만 스테이징·커밋합니다. 0.4.0부터는 `<project>/.git` 이력을 전혀 더럽히지 않는 별도 Shadow Git 저장소(`%APPDATA%\Ned\checkpoints\`)에 수정 전 체크포인트를 자동 생성해 파일 단위·전체 복원을 지원하고, `worktree_sandbox`로 격리된 작업 트리에서 병렬 실험·구현을 수행합니다.


일괄 수정 직후 앱이 중단됐다면 해당 프로젝트를 다시 열고 “미완료 일괄 변경 복구 목록을 보여줘”라고 요청할 수 있습니다. 표시된 기록의 복구를 요청하면 Ned가 바뀐 파일과 스냅샷을 확인하고, 미저장 버퍼와 승인 정책을 적용합니다. 복구 대상에 이후 편집한 파일이나 스냅샷을 확인할 수 없는 파일이 포함되면 변경 없이 문제 경로를 안내합니다.

### 3.7 Windows 터미널(CMD·PowerShell) 작업

- **자연어 요청 예시**: "PowerShell로 빌드 산출물 크기를 확인하고 테스트 스크립트를 실행해줘"
- **자동 연결 도구**: `run_terminal`, `terminal_status`, `stop_terminal`
- **동작 특징**: 일반 개발·빌드·테스트 명령은 전체 권한 모드에서 승인창 없이 빠르게 실행되지만, 디스크 포맷·레지스트리/방화벽/서비스 변경·프로젝트 외부 재귀 삭제·외부 네트워크 전송·중첩 셸 우회·동적 평가(`iex`, `-EncodedCommand`) 같은 고위험 명령은 전체 권한 모드에서도 반드시 명시적 승인 팝업을 띄웁니다.

### 3.8 사내 문서 읽기·양방향 생성(HWP/HWPX·MS Office) 및 로컬 데이터·통계 분석

## 4. 실전 요청 시나리오 4가지

자연어로 목표와 제약만 알려 주면 Ned가 내부적으로 어떤 흐름을 밟는지 4가지 대표 사례로 살펴보겠습니다.

### 사례 1. "실행할 때 간헐적으로 멈추는 원인을 찾아 고치고 테스트해줘"
1. Ned가 요청의 오류·원인 추적 의도를 인식해 `diagnosing-bugs`와 `systematic-debugging` 스킬을 자동 주입합니다.
2. 과거에 비슷한 장애를 해결한 기록이 있으면 OpenViking 개인 기억을 자동 회상합니다.
3. 에이전트가 `search_text`, `read_file`, `git_inspect`, `ast_search`로 의심 코드를 확인한 뒤 `patch_file`로 최소 범위만 수정합니다(수정 직전 Shadow Git 체크포인트 자동 보존).
4. `run_python` 또는 `run_terminal`로 관련 테스트를 실제 실행하고, 통과한 검사와 미실행 검사를 구분해 보고합니다.

### 사례 2. "사양서 PDF·HWPX를 읽고 기존 C++ 파서 코드와 다른 부분을 정리한 뒤 보고서를 Excel로 만들어줘"
1. 에이전트가 `document_read`(MarkItDown·`kordoc`·`pdfplumber`)로 로컬 PDF 표와 HWPX 원문을 읽습니다.
2. C++ 파서 파일은 `semantic_symbols`(Serena + clangd)와 `read_file`로 구조와 함수 정의를 확인합니다.
3. 두 근거를 대조한 결과를 `document_write`로 구조화된 `.xlsx` 보고서로 생성합니다.

### 사례 3. "이 React 화면의 간격과 접근성을 개선하고 로컬 서버에서 직접 확인해줘"
1. Ned가 `unslop`, `modern-web-guidance`, `ui-accessibility`(Astryx 요청 시 `astryx`) 스킬을 자동 주입합니다.
2. `patch_file`로 컴포넌트를 수정하고 `browser_check`(Playwright/DevTools)로 로컬 개발 페이지의 접근성 스냅샷과 콘솔 오류를 확인합니다.

### 사례 4. "이건 기억하지 마. 임시 테스트 계정 설정이 들어 있는 파일에서 오타만 찾아줘"
1. Ned가 `"이건 기억하지 마"` 표현을 감지해 해당 턴의 개인 기억 회상과 자동 수집·커밋을 모두 건너뜁니다.
2. 혹시 대화나 질의어에 API 키·JWT·PEM 개인키·DB 자격증명·비밀번호가 섞이더라도 시크릿 마스킹이 회상과 저장 양쪽에서 민감 문자열을 제거합니다.

## 5. 자동 동작을 사용자가 직접 제어하는 방법

자동 연결이 기본값이지만, 모든 자동 동작은 사용자가 직관적으로 확인하고 제어할 수 있습니다.

### 5.1 스킬 직접 지정 또는 끄기
- **특정 스킬 직접 호출**: 대화 입력창에 `/skill-<스킬이름>` 형태로 입력하면 해당 스킬 문서를 명시적으로 불러옵니다. (사용자 글로벌 스킬은 `%APPDATA%\Ned\skills`, 프로젝트 스킬은 프로젝트 내부 `.ned\skills`에 추가하면 재시작 없이 바로 사용할 수 있습니다.)
- **해당 턴 자동 스킬 끄기**: 요청에 `"스킬 사용하지 마"` 또는 `"스킬 쓰지 마"`를 포함하면 그 턴에는 자동 스킬 주입을 생략합니다.

### 5.2 자동 대화 기억 제어
- **한 턴만 제외**: 요청에 `"이건 기억하지 마"`, `"메모리 쓰지 마"` 등을 넣으면 해당 턴의 회상과 저장을 모두 건너뜁니다.
- **세션 전체 제외**: `"이 세션은 기억하지 마"`, `"이번 대화는 저장하지 마"`라고 말하면 해당 세션의 이후 모든 턴을 제외하며, 세션을 다시 열어도 제외 상태가 유지됩니다.
- **전역 설정 변경**: 설정 JSON의 `openViking.memory` 항목에서 `enabled`(기본 `true`), `autoRecall`(기본 `true`), `commitEveryTurns`(기본 `6`, 허용 범위 `1`~`50`)를 조정한 뒤 트레이의 **설정 JSON 가져와 적용 (자동 재시작)**으로 반영할 수 있습니다.
- **실시간 상태 확인**: Windows 알림 영역의 Ned 트레이 메뉴에서 자동 대화 기억의 현재 상태(`준비 중` / `켜짐` / `오류` / `꺼짐`)를 바로 확인할 수 있습니다.

### 5.3 권한 모드 3단계 조절
대화 입력창 또는 알림 영역의 **권한** 메뉴에서 모드를 바꿀 수 있으며, 선택은 재시작과 업데이트 후에도 유지됩니다.

| 권한 모드 | 자동 승인 범위 | 명시적 확인 필요 |
| :--- | :--- | :--- |
| **승인 요청** (기본값) | 프로젝트 내부 읽기·검색 | 파일 수정·삭제, 외부 읽기, 셸 명령, Git 쓰기, 빌드, 지식 저장·색인, 데스크톱 조작, 패키지 설치 |
| **프로젝트 파일 자동 승인** | 프로젝트 내부 파일 생성·수정·삭제 | 외부 읽기, 셸 명령, Git 쓰기, 빌드, 지식 저장·색인, 데스크톱 조작, 패키지 설치 |
| **전체 권한** | 프로젝트 파일 변경, 외부 로컬 읽기(개인 키·프로필 제외), 일반 셸 명령, Git 커밋, 빌드, 분석, 지식 저장·조회, 데스크톱 조작 | 고위험·외부 전송 셸 명령, 비루프백·변경성 OpenAPI 테스트, Python 환경 최초 선택, 제품 방향 결정 (외부 파일 쓰기는 항상 차단) |

### 5.4 기본 Zed Agent와 Ned Agent 구분
- **Ned Agent**(`Ctrl+Shift+A`): 이 문서에서 설명한 자동 스킬 라우팅, 40여 종 호스트·MCP·Workspace 도구, OpenViking 지식·개인화 기억, Ned 권한 모드를 모두 사용합니다.
- **기본 Zed Agent**: 중앙 JSON의 사내 모델 연결만 공유하고 Ned의 스킬·도구·지식을 주입하지 않은 채 Zed 자체 도구만 사용합니다. 필요에 따라 대화 스레드별로 골라 쓸 수 있습니다.

## 6. 폐쇄망 안전 원칙과 현실적인 한계

### 지켜지는 안전 원칙
- **완전 폐쇄망 동작**: 모든 런타임·토크나이저·스킬·Ghidra·브라우저·Workspace Tools는 빌드 시 버전과 SHA-256 해시를 고정해 반입 TGZ에 포함합니다. 직원 PC에서 외부 인터넷 다운로드·자동 업데이트·외부 텔레메트리 전송을 시도하지 않습니다. (사내 PyPI `.venv` 설치는 사내 미러 라우팅이 구성된 환경에서 사용자 요청으로만 동작합니다.)
- **자격증명과 개인 프로필 격리**: API 키는 Windows DPAPI(사용자 보호 암호화)로만 저장하고 로컬 게이트웨이 메모리에 격리합니다. 직원의 기존 개인 Zed·OpenCode 설정이나 `.ssh`·`.aws` 등 자격증명 폴더를 몰래 읽거나 덮어쓰지 않습니다.
- **업데이트 시 사용자 자산 보존**: 새 버전 EXE로 업데이트해도 모델 설정, 권한 모드, 대화 이력, OpenViking 지식·기억, 사용자 글로벌 스킬, Zed 글꼴·테마·패널 배치를 보존합니다.
- **사내 대기열 존중**: 사내 LLM 응답 생성에는 임의의 기본 경과 시간 제한을 두지 않으며, 사용자가 중지 버튼을 누를 때만 소유한 자식 프로세스까지 함께 정리합니다.

### 도입·사용 시 알아 둘 한계
- **모델 자체의 재학습은 아닙니다**: 자동 스킬 라우팅과 개인화 기억은 모델에 더 정확한 절차와 근거를 공급하는 장치입니다. 답변과 수정 코드는 반드시 실제 빌드·테스트·코드 리뷰로 확인해야 합니다.
- **프로젝트 환경 준비가 정확도를 좌우합니다**: C/C++ 의미 분석에는 `compile_commands.json`과 헤더 경로가, MSBuild와 Conda 실행에는 PC에 사전 설치된 VS2017/2019/2022·SDK·Conda 환경이 필요합니다.
- **검증 환경 구분**: 자동화된 Linux 단위 테스트 및 Windows Server 오프라인 설치·업데이트 검증과, 실제 직원 PC(Windows 10·11 GUI, 사내 VLM·임베딩·PyPI 서버, 외부망 차단 환경)에서의 최종 수용 검증은 별도로 구분해 관리합니다.

## 7. 빠른 시작 체크리스트

1. 반입 TGZ 압축을 새 폴더에 풀고 `Ned-0.4.0-win-x64.exe`를 실행합니다. (업데이트 시 실행 중인 Ned와 개인 Zed를 먼저 종료합니다.)
2. 최초 설치라면 `%APPDATA%\Ned\config-import.json`에 사내 LLM과 OpenViking 임베딩 모델 정보를 입력합니다. (이후 설정 변경은 트레이의 **설정 JSON 가져와 적용 (자동 재시작)** 사용)
3. 알림 영역의 **Ned → 프로젝트 폴더 열기**로 작업 폴더를 열고, Zed에서 `Ctrl+Shift+A`로 Ned 대화를 시작합니다.
4. 처음에는 익숙한 코드 설명이나 작은 버그 수정처럼 결과를 직접 판단할 수 있는 자연어 요청으로 시작해, Ned가 어떤 스킬과 도구를 자동으로 연결하는지 확인해 보세요.
