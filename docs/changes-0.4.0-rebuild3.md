# Ned 0.4.0 rebuild3 변경 사항

0.4.0 제품 버전을 유지합니다. 공개 rebuild2의 제품 소스와 당시 main을 대조하고, 파일 쓰기·복구, OpenViking 비동기 기억, 패키지 실행·문서·도구 라우팅을 확인했습니다. rebuild2는 대용량 출력 처리, 다중 파일 복구, 사내 Python 환경 실행 시 승인, 비동기 기억 추적과 설치 백업을 추가했습니다.

- **중단된 REA 분석 이어가기**. 기존에는 최근 두 요청의 키워드로 도구를 열었고, 중지하면 호스트 쪽 요청 기록이 삭제됐습니다. 같은 세션에서 사용자가 명시적으로 REA/Ghidra 분석을 요청한 뒤 “답변을 이어서 달아줘”, “계속해줘”처럼 이어갈 때 모델과 호스트가 동일한 REA 의도를 사용합니다. 재연결 시 승인된 세션의 최근 사용자 기록에서 복구합니다. 새로운 작업, 명시적인 사용 중지, 다른 세션에는 적용하지 않습니다. 기존 파일 범위와 실행 승인 정책을 유지합니다.
- **다중 파일 롤백**. 먼저 반영한 파일에 다른 변경이 생기면 해당 파일을 자동 복구 대상에서 제외하고 파일과 스냅샷을 알려줍니다. 사용자가 새로 쓴 내용을 덮어쓰거나 삭제하지 않습니다.
- **업데이트 백업 복구**. 이전 실행이 남긴 백업을 같은 설치 경로에서 다시 시도할 때 먼저 복구합니다. 잠금이나 권한 문제로 복구하지 못한 파일은 백업에 보존하고 설치를 중단합니다.

## 다음 교차 검토 우선 항목

- [OpenViking 기억 작업 추적](../src/main/session-memory.ts). 복구 대상은 세션 커밋과 이미 생성된 아카이브의 추출을 구분해야 합니다. 작업 ID 조회가 404/unknown이면 현재 대기 턴과 작업 참조를 지웁니다. OpenViking 0.5.5는 아카이브 추출 재시도 API를 별도로 제공하므로 아카이브 ID 보존과 재시작·실패 재처리를 검증해야 합니다.
- [업데이트 복구](../distribution/ned/installer.nsi). 이번 복구 대상은 resources, locales, Ned.exe입니다. 전체 설치 폴더의 파일 세트를 하나의 단위로 교체하는 단계와 강제 종료 후 이어서 복구하는 임의 시점 시험이 남아 있습니다.
- [다중 파일 적용](../src/main/files.ts). 처리 중인 파일의 목록은 메모리에 있습니다. 앱이나 PC가 중간에 종료된 경우 재시작 시 적용·복구 진행 상태를 이어받는 기록이 필요합니다.
- [정적 프리뷰](../distribution/data-apps.ts). Python http.server는 문서 루트 아래 링크를 따라갈 수 있습니다. 프로젝트 경로 확인은 서버 시작 때만 이루어지므로 파일을 요청할 때도 심볼릭 링크·junction을 포함한 경계를 확인해야 합니다.
