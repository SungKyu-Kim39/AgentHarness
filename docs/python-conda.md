# Conda 환경으로 Python 실행·검증·빌드하기

Ned 0.3.8은 PC에 이미 설치된 Conda 환경을 찾아 프로젝트의 실행 환경으로 지정할 수 있습니다. 환경을 한 번 선택하면 같은 프로젝트 폴더에서는 이후에도 그 환경을 사용합니다. 설치된 패키지를 활용하며, 폐쇄망에서 Conda·pip 패키지를 내려받는 절차는 제공하지 않습니다.

## 처음 사용하는 프로젝트

> 이 PC의 Conda 환경을 찾아 주세요. 사용할 환경은 제가 고른 뒤, 그 환경으로 `main.py`를 실행해 주세요. 이후에도 이 프로젝트에서는 같은 환경을 사용해 주세요.

Ned는 사용자·공용 설치 위치, Conda 설치 레지스트리, `.conda/environments.txt`와 Conda의 `info --envs --json` 결과를 조사합니다. **프로젝트의 Python 환경 선택** 창에서 환경 이름과 경로를 확인하고 **이 환경 사용**을 누릅니다. 전체 권한을 선택했더라도 이 환경 선택은 대신 결정하지 않습니다.

자동으로 찾지 못했거나 다른 설치본을 쓰려면 **다른 Conda 설치 찾기**에서 Conda 설치 루트 폴더를 선택합니다. 예를 들어 `D:\Tools\Miniconda3`처럼 `Scripts\conda.exe`, `condabin\conda.bat`가 있는 폴더입니다. `envs\analysis` 환경 폴더만 선택하는 것과 구분하세요.

선택한 환경이 없어졌거나 Python 실행기가 바뀌어 확인할 수 없으면 오류를 표시합니다. base 환경이나 Ned의 OpenViking용 Python으로 자동 전환하지 않습니다. 환경 변경을 원할 때만 다음처럼 요청합니다.

> 이 프로젝트에서 사용할 Conda 환경을 다시 선택하겠습니다. 환경 선택창을 열어 주세요.

## 실행과 빌드 요청 예시

| 요청 | 실제 작업 |
| --- | --- |
| “선택한 환경으로 `main.py`에 `--input data.csv`를 전달해 실행해 주세요.” | 환경 활성화 후 저장된 프로젝트 `.py` 파일을 실행합니다. |
| “`main.py`의 Python 바이트코드 컴파일을 확인해 주세요.” | 선택한 Python의 `py_compile`을 사용합니다. 프로젝트에 `__pycache__`가 생길 수 있습니다. |
| “선택한 환경에서 `tests/test_core.py`만 pytest로 확인해 주세요.” | 해당 환경에 설치된 pytest를 실행합니다. |
| “이 프로젝트를 wheel로 빌드해 주세요.” | 설치된 `build` 모듈의 `--no-isolation --wheel`을 사용하고 `dist`에 저장합니다. |
| “`main.py`를 단일 EXE로 패키징해 주세요.” | 선택한 환경에 설치된 PyInstaller의 `--onefile`을 사용합니다. `build`·`dist`는 프로젝트 안에 생성하고 spec 파일은 Ned의 작업 임시 폴더에 생성합니다. 기존 사용자 spec 파일을 덮어쓰지 않습니다. |

Python은 C/C++와 빌드 방식이 다릅니다. `.py` 실행, 문법·바이트코드 검사, 테스트, wheel 패키지 생성, PyInstaller EXE 생성 중 어떤 결과가 필요한지 구체적으로 말하면 작업을 분명하게 지정할 수 있습니다. 의존성이 없으면 해당 환경에 필요한 패키지가 없다고 알립니다. 관리자나 배포 담당자가 폐쇄망에 맞춰 패키지를 준비해야 하며 Ned가 자동 설치하지 않습니다.

`run_python`은 작업 ID를 반환합니다. 시작했다는 응답만으로 성공했다고 표시하지 않으며 `python_run_status`에서 완료 상태·실제 종료 코드·출력을 확인합니다. 긴 실행은 같은 작업 ID로 상태를 이어서 확인합니다. **중지**를 요청하면 해당 Ned 작업이 소유한 자식 프로세스만 종료하며 다른 Conda·Python·OpenViking은 건드리지 않습니다. 동시에 두 프로젝트까지 실행합니다.

프로젝트 코드는 디스크에 저장된 내용을 실행합니다. 필요한 파일을 먼저 저장하세요. 실행 승인 뒤 입력 파일이 달라지면 실행을 보류합니다. 현재 터미널에서 사용자가 직접 입력하는 대화형 `input()` 프로그램은 지원하지 않습니다.

## 권한과 실행 범위

Conda 실행기를 통한 목록 조회와 Python 실행에는 명령 권한 정책을 적용합니다. **전체 권한**에서는 지원하는 실행의 승인창을 생략하고, 환경 선택창은 최초 선택·명시적 변경 때만 엽니다. 나머지 모드에서는 실제 실행 파일·인자·작업 폴더·입력 해시를 확인한 뒤 승인합니다.

Ned가 작성한 고정 실행 절차로 Conda를 활성화하고 선택한 환경의 Python을 사용합니다. 모델이 임의의 셸 명령이나 인터프리터 경로를 지정하지 않습니다. 스크립트 인자는 JSON으로 전달하여 셸에서 다시 해석하지 않습니다. 환경의 활성화 스크립트와 프로젝트 코드 자체는 실행되므로, 이 기능이 프로그램 전체의 파일·네트워크 동작을 제한하는 OS 샌드박스는 아닙니다. 프로젝트 밖의 파일 생성·수정·삭제는 여전히 Ned 파일 도구에 허용하지 않습니다.

추가 옵션은 작업별로 제한합니다. 스크립트 실행은 일반 인자를 지원하고, `compile`·`wheel`에는 추가 인자를 받지 않습니다. PyInstaller는 `--onefile`, `--onedir`, `--windowed`, `--console`, `--clean`, `--noupx`를 지원합니다. pytest는 프로젝트 안의 대상, `-k`·`-m` 필터, `-q`·`-v`·`-vv`·`-x`·`-s`·`--maxfail=N`·`--tb`·`--disable-warnings`를 지원합니다.

## 프로젝트 기억은 어디에 저장하나

선택은 `%APPDATA%\Ned\python-projects\<프로젝트 ID>.json`에 저장합니다. ID는 정규화한 프로젝트 폴더 경로를 기준으로 구분합니다. 업데이트·재시작 후에도 유지되며 다른 프로젝트의 선택을 가져다 쓰지 않습니다.

OpenViking이 활성화되어 있으면 같은 선택을 그 프로젝트의 `ned-python-environment-<선택 ID>.md` 지식으로 기록합니다. 선택 이력은 버전별로 보존하며 환경 이름·경로·선택 시각만 기록하고 키·환경 변수 값·대화·실행 출력은 올리지 않습니다. OpenViking이 꺼져 있거나 기록에 실패해도 로컬 선택은 보존하며 다음 사용 때 기록을 다시 시도합니다. 상태의 `memory: pending`은 아직 OpenViking 기록이 확인되지 않았다는 뜻이고 `ready`는 기록을 확인했다는 뜻입니다.

OpenViking의 글은 참고 자료이며 실행 권한의 근거가 아닙니다. 실제 실행 환경은 사용자가 선택한 로컬 기록과 현재 파일을 다시 확인합니다. 다른 사람이 지식 문서를 바꾸는 것만으로 Python 실행 경로가 바뀌지 않습니다.
