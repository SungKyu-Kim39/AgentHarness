# Ned Core와 선택형 리버싱 팩 (0.3.11 보관 문서)

> Ned 0.3.12부터 Core·리버싱 팩 이원화를 제거하고 전체 설치본 단일 배포로 전환했습니다. 이 문서는 0.3.11 배포 참고용으로 보관합니다.

Ned 0.3.11의 전체 설치본은 기존 도구를 함께 설치합니다. Core 설치 EXE는 편집기, Ned Agent, Git, OpenViking, 기본 스킬과 나머지 개발 도구를 제공합니다. Core에서 REA와 Ghidra/OpenJDK는 별도 리버싱 팩으로 제공됩니다.

## 0.3.11 배포 파일 비교

| 배포 파일 | 다운로드 크기 | 파일 수 |
| --- | ---: | ---: |
| 전체 설치 EXE | 1,535,010,935바이트 (약 1.535 GB) | 설치 파일 60,118개 |
| Core 설치 EXE | 1,032,201,071바이트 (약 1.032 GB) | 설치 파일 47,445개 |
| 리버싱 팩 TGZ | 696,498,605바이트 (약 696.5 MB) | 압축 안 12,678개, 설치 런타임 12,673개 |

EXE 파일 수는 설치기 내부 보조 파일과 제거 프로그램을 제외한 기준입니다. 팩에는 런타임 외에 대응 소스와 설치 안내·스크립트 등 5개 파일이 들어 있습니다. 공개 파일의 SHA-256과 각 압축의 파일 목록을 대조했습니다. [설치 감사 기록](../validation-0.3.11.md) · [공개 파일 검증 기록](../../downloads/Ned-0.3.11-public-verification.json)

Core만 배포하면 전체 EXE 대비 다운로드가 약 **503 MB(32.8%)** 줄고 설치 파일이 **12,673개(21.1%)** 줄어듭니다. 리버싱이 필요한 PC에 Core와 팩을 함께 반입할 때 다운로드 합계는 약 1.729 GB입니다.

## 리버싱 팩 설치

1. 같은 버전의 Core EXE와 리버싱 팩 TGZ를 반입하고 공개 SHA-256과 대조합니다.
2. Core를 설치합니다. Ned를 종료하고 TGZ를 로컬 폴더에 풉니다.
3. 사내 정책이 허용하는 PowerShell에서 풀어 놓은 폴더의 `INSTALL.ps1`을 실행합니다. 스크립트는 설치된 Ned의 버전과 구성 요소별 고정 SHA-256을 확인합니다.
4. Ned를 다시 시작합니다. Ned Agent에 프로젝트 내부 바이너리의 리버싱이나 Ghidra 분석을 명시적으로 요청합니다.

팩은 `%APPDATA%\Ned\packs\reversing\<version>`에 설치합니다. 같은 Ned 버전을 재설치해도 해당 폴더는 보존됩니다. 버전이 바뀌면 해당 버전의 팩을 설치합니다. 제거하려면 Ned를 종료하고 해당 팩 버전 폴더를 삭제합니다. 전체 설치본에는 분석 런타임이 포함되어 있어 별도 설치가 필요하지 않습니다.

설치 파일과 팩은 인터넷 다운로드를 실행하지 않습니다. 사내 배포 전에는 [직원 PC 우선 확인 항목](../windows-acceptance.md#0311-정식-배포-전-우선-확인)에서 PowerShell 실행 정책을 확인합니다. 사내 배포용 서명과 애플리케이션 실행 정책은 [라이선스 및 배포](../license-policy.md)에서 확인합니다.
