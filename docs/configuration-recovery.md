# Ned 설정 파일 변경과 복구

Ned는 첫 실행에 사용할 평문 JSON과 실제로 저장하는 암호화 설정을 나누어 관리합니다. 이 차이를 알면 `config-import.json`이 없거나 모델이 바뀌지 않는 상황을 쉽게 확인할 수 있습니다. 아래는 0.3.2부터 지원하는 설정 가져오기·자동 재시작 절차입니다.

## 두 파일의 역할

| 파일 | 역할 |
| --- | --- |
| `%APPDATA%\Ned\config-import.json` | 최초 가져오기용 임시 평문 JSON. 검증·암호화 저장 후 삭제합니다. |
| `%APPDATA%\Ned\settings.enc.json` | Windows 사용자 보호 기능으로 암호화한 저장 설정. 직접 편집하지 않습니다. |

`settings.enc.json`만 있고 `config-import.json`이 없는 것은 정상일 수 있습니다. 첫 실행에서 준비 파일을 처리했거나, 설치 전에 저장 설정이 있어 임시 파일 생성을 건너뛴 경우입니다. 설치기에서는 메모장 실행도 함께 생략합니다. 업데이트·제거 후 재설치에서도 저장 설정을 유지하며, 손상된 설정을 자동으로 덮어쓰지 않습니다.

파일 존재 여부만으로 복호화와 모델 연결 성공까지 판단할 수는 없습니다. 실행 결과와 함께 확인해야 합니다.

## 모델 설정 바꾸기

1. TGZ의 `agent-config.json`을 별도 파일로 복사합니다. 묶음이 없다면 기본 설치 위치의 `%LOCALAPPDATA%\Programs\Ned\resources\ned\agent-config.example.json`을 사용합니다. 다른 경로에 설치했다면 실제 설치 폴더에서 찾습니다.
2. 복사본을 편집합니다. 유지할 모든 LLM provider·모델과 단일 `openViking.embedding`에 사내 주소·키·ID를 입력합니다. 가져오기는 전체 설정 교체이므로 계속 사용할 provider도 포함해야 합니다. `REPLACE_...`와 `.internal.example`은 예제 값입니다.
3. 진행 중인 작업을 마치고 Windows 알림 영역의 Ned 아이콘을 오른쪽 클릭합니다. 아이콘이 접혀 있다면 숨겨진 아이콘 표시를 엽니다.
4. **설정 JSON 가져와 적용 (자동 재시작)**에서 편집한 파일을 선택합니다. 검증·암호화 저장 후 편집기를 정상 종료하고 서비스를 닫은 뒤 새 설정으로 다시 실행합니다. Zed의 저장 확인창이 나오면 저장을 마칩니다.
5. 시작 단계의 오류창에 머물러 있다면 **설정 JSON 가져와 교체**를 사용합니다. 저장 설정이 없는 첫 실행에서는 **설정 JSON 가져오기**로 표시합니다.

저장을 취소하면 편집기와 서비스는 유지하고 재시작을 대기합니다. 이후 모든 편집기 창을 정상 종료하면 다시 실행합니다. **설정 적용 재시작 대기 취소**는 자동 재시작 예약만 취소하며, 이미 저장한 설정은 다음 실행 때 적용합니다.

잘못된 JSON이나 암호화 저장 실패로 편집기를 닫지는 않습니다. 서비스 종료가 확인되지 않으면 새 인스턴스도 시작하지 않습니다. 암호화 파일이나 사용자 대화·DB·프로젝트를 삭제할 필요는 없습니다. 다른 Windows 계정에서 암호화한 설정은 복호화되지 않을 수 있습니다.

선택한 원본 JSON은 사용자가 보관하는 평문 파일입니다. 앱이 삭제하는 것은 자신의 `config-import.json` 사본뿐입니다. 실제 키를 넣은 원본의 보관·폐기를 관리하고, 키나 설정 전문은 지원 채팅·공개 저장소에 보내지 마세요.

## 모델 목록과 연결 오류 확인

설치 폴더의 `agent-config.json`을 수정해도 저장 설정은 그대로입니다. 이미 설치한 앱에는 위 가져오기 메뉴로 적용해야 합니다. OpenViking 시작 패치도 LLM 설정을 초기화하거나 새 모델을 등록하지 않습니다.

목록이 비어 있는 경우에는 편집기와 엔진의 모델 목록 연결을 확인합니다. 모델이 표시되는데 요청만 실패한다면 선택한 모델의 실제 오류를 확인합니다. 두 현상을 API 키 문제로 한꺼번에 판단하지 않는 편이 좋습니다. 모델 선택창은 등록된 모델 사이를 바꾸는 곳입니다.

`사내 코딩 모델`은 기본 예제의 표시 이름입니다. `providers.<key>.name`과 `models.<key>.name`을 바꿔 구분할 수 있지만, 이름이 바뀌었다고 주소·키·서버 ID까지 적용된 것은 아닙니다. 실제 요청 결과도 확인하세요.

## JSON에서 확인할 항목

`model.providerID`는 `providers`의 키와, `model.model`은 그 provider 안의 `models` 키와 일치해야 합니다. provider가 `Qwen think_off`, 모델 별칭이 `model-1`이라면 `"model": { "providerID": "Qwen think_off", "model": "model-1" }`로 지정합니다. 서버에 보낼 ID는 해당 모델의 `modelID`에 둡니다.

provider 한 개 뒤의 `},`에서 파일을 끝내거나 마지막 항목 뒤에 쉼표를 두면 문법 오류가 납니다. 열린 객체를 모두 닫고, `providers` 뒤에 다른 최상위 항목이 있으면 사이에 쉼표를 넣어야 합니다. 실제 JSON에는 Markdown 코드 블록 표시를 넣지 않습니다.

provider 키는 `Qwen think_off`인데 `providerID`를 `intranet`으로 쓴 경우는 참조 오류입니다. JSON 문법 검사와 별도로 확인해야 합니다.

설정 보존은 [설치기](../distribution/ned/installer.nsi), 임시 파일 삭제·암호화 저장은 [ConfigVault](../src/main/config.ts), 오류창과 메뉴는 [Ned 호스트](../distribution/ned/main.ts)에서 처리합니다. 배포 PC의 오류는 해당 환경의 실행 결과와 함께 확인합니다.
