# EGM 설계·검토 워크플로

Google elephant-goldfish-model 0.1.1의 문서를 커밋
`72d06f52a2482885d9a64bd24b291c6e8628942c`에 고정했습니다. Apache-2.0 원문과
모든 워크플로·검토자·기준 문서를 오프라인 스킬 자료로 제공합니다. 정확한 파일 해시는
`egm-lock.json`과 스킬 manifest에 있습니다. 원본의 실험적 OpenCode 1.18.29용 설치기는
실행하지 않으며 Ned의 OpenCode 2.2.6 호스트 도구에 맞춘 어댑터를 사용합니다.

| 요청할 스킬 | 용도 |
| --- | --- |
| egm-brainstorm | 아이디어·요구·대안과 개념 문서 |
| egm-draft | 구현 전 설계 작성 |
| egm-review | 단계별 설계 검토 |
| egm-review-loop | 지정 기준·검토자의 독립 리뷰 |
| egm-resolve | 지적 사항 검토와 합의한 문서 수정 |
| egm-bootstrap | 기존 코드에서 설계 문서 작성·갱신 |
| egm-drift-report | 설계와 코드의 차이 보고 |

예를 들어 Ned Agent에 “egm-draft로 이 기능의 설계를 작성해줘”라고 요청합니다.
기본 Zed Agent에는 Ned의 스킬·도구를 연결하지 않으므로 같은 동작을 제공하지 않습니다.

Elephant는 문맥과 사용자 결정을 관리하는 주 Agent입니다. 독립 검토는 매번 새로운
`goldfish` 하위 세션에서 고정된 검토자를 지정해 실행합니다. 부모 대화와 개인 기억을
전달하지 않고 자동 스킬 주입도 생략합니다. Goldfish에는 프로젝트 읽기·목록과 EGM
문서 읽기만 허용하고, 메모리 조회·수정·빌드·Git·GUI·재위임을 호스트에서 차단합니다.
전체 하위 Agent 동시 실행 한도는 기존과 같은 두 개이며 나머지는 대기합니다.

필수 자료를 읽지 못하거나 검토 결과가 없으면 완료로 간주하지 않습니다. 설계 승인과
상충하는 요구 결정은 사용자가 합니다. EGM 설계 작업 중에는 제품 코드를 바꾸지 않으며,
별도 구현 지시가 있으면 일반 구현 작업으로 전환합니다. 원본 문서가 권한이나 외부 설치를
부여하지 않습니다. 모든 일반 대화에 EGM을 자동 적용하지 않습니다.

공용 원본 자료는 `read_skill id=egm-review-loop`의 `references/bundle/` 아래에 있습니다.
긴 문서는 반환되는 offset으로 끝까지 읽습니다. 실제 사내 모델의 검토 품질과 결과 통합은
설치 후 수용 항목이며 호스트 권한 테스트만으로 검토 품질까지 보장하지 않습니다.
