# 기본 Zed Agent와 Ned Agent 선택

0.3.8 rebuild1부터 같은 편집기에서 두 가지 Agent를 사용할 수 있습니다. New Agent Thread에서 Ned를 선택하면 기존 Ned Agent가 실행됩니다. 외부 Agent가 아닌 Zed 기본 Agent로 대화를 시작하고 Intranet 제공자의 모델을 고르면 Zed 자체 Agent를 사용합니다. 두 방식 모두 agent-config.json에 등록한 사내 모델에 연결합니다. 모델 이름이 비슷하더라도 등록한 제공자와 서버 주소는 구별됩니다.

| 항목 | Ned Agent | 기본 Zed Agent |
| --- | --- | --- |
| 에이전트 실행 | 번들 OpenCode와 Ned ACP | Zed 내장 Agent |
| 코드 읽기·편집·터미널 | Ned 호스트 도구·선택한 권한 모드 | Zed 자체 도구·Zed 자체 승인 |
| Aegis·Conductor·기본 스킬 | 제공 | 자동 주입하지 않음 |
| Serena·Graphify·REA·agent-desktop | Ned가 중계 | 연결하지 않음 |
| OpenViking 지식·프로젝트별 Python 환경 기억 | 제공 | 연결하지 않음 |
| Ned 요약 재시도 정책 | 적용 | 적용하지 않음 |
| 사내 모델 JSON | 사용 | 같은 모델 목록과 기본 요청 옵션 사용 |

Zed 기본 Agent를 택하면 Ned의 전체 권한 설정으로 Zed 자체 승인을 생략할 수는 없습니다. Zed의 Write·Ask·Minimal 프로필과 자체 권한 설정을 사용합니다. 기본 프로필은 Write이며 이후 선택은 업데이트·재시작 시 유지합니다. 등록한 모델이 제거되면 JSON의 기본 모델로 돌아갑니다.

실제 사내 API 키는 Zed 설정 파일에 쓰지 않습니다. 실행마다 발급하는 로컬 연결 자격증명으로 Ned의 모델 중계를 거치며, 이 중계는 모델 주소·인증·기본 요청 옵션만 처리합니다. Zed의 대화·도구 정의·요약 요청에 Ned 지침이나 도구를 추가하지 않습니다. 사내 대기열을 기다리는 생성 요청에는 임의의 기본 시간 제한을 두지 않습니다. 중지는 사용자가 요청할 수 있습니다.

폐쇄망용 편집기 설정에 따라 웹 검색·fetch와 임의 MCP 자동 연결은 끕니다. 기존 개인 Zed 설정이나 스킬을 복사하지 않습니다. 프로젝트의 AGENTS.md 등 Zed가 원래 읽는 지침은 그대로 적용될 수 있으며, 사용자가 요청했던 한국어 응답 지침은 공통 편집기 프로필에 유지합니다. 이는 별도 운영체제 사용자나 샌드박스로 격리한 제품은 아닙니다. Zed의 터미널과 파일 도구는 그 도구의 권한과 운영체제 계정 권한을 따릅니다.

왼쪽 상단 메뉴와 About 화면은 Ned로 표시합니다. About에는 Ned 0.3.8 rebuild1과 기반 Zed 1.28.1의 버전·소스 정보를 함께 표시합니다. 기본 Agent의 이름으로 쓰이는 Zed와 원본 저작권·라이선스 표시는 기능과 출처를 구분하기 위해 유지합니다.
