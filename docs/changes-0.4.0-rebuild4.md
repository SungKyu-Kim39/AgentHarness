# Ned 0.4.0 rebuild4 변경 사항

0.4.0 제품 버전을 유지합니다. `0.4.0-rebuild3`(`194567f`)을 기준으로 전체 교차 검토를 수행해 업그레이드 복구·정적 프리뷰 경계·OpenViking 0.5.5 비동기 기억 수명 주기·전문 도구 이어하기·다중 파일 크래시 복구 저널 5건을 보완하고, 사용자 요청에 따라 **REA 전용 대화 모드**를 추가했습니다.

- **REA 대화 모드 추가 및 Plan/Build 모드 경고** ([`distribution/native-control.ts`](../distribution/native-control.ts), [`distribution/ned/agent.ts`](../distribution/ned/agent.ts), [`distribution/ned/owner.ts`](../distribution/ned/owner.ts), [`distribution/host-tools.ts`](../distribution/host-tools.ts), [`src/main/skill-routing.ts`](../src/main/skill-routing.ts), [`src/main/model-gateway.ts`](../src/main/model-gateway.ts)): 기존 `Build`·`Plan` 대화 모드에 더해 기본 에이전트 목록에 `REA` 대화 모드(`mode: "primary"`)를 추가했습니다. `REA` 모드에서는 사용자가 프롬프트에 Ghidra나 REA를 명시하지 않아도 필요할 때 `rea_ghidra`·`rea_inspect` 도구를 즉시 사용할 수 있으며(중단·컴팩션·재연결 및 하위 `research` 에이전트에서도 부모 세션의 `REA` 모드를 유지), 정적 분석 전용 경계와 네이티브 승인 정책은 그대로 유지합니다. 반대로 `Plan` 또는 `Build` 모드에서는 `rea_*` 도구를 숨기고, REA·바이너리 역공학 요청이 들어오면 모델에게 `REA` 모드 전환 안내를 주입하며, 호스트 도구(`HostTools`)에서 `rea_ghidra`·`rea_inspect` 호출이 시도되면 대화 모드를 `REA`로 변경해야 한다는 경고와 함께 실행을 차단합니다. ACP 브리지(`distribution/ned/agent.ts`)는 Zed 드롭다운의 표시 이름을 `REA`로 맞추고 `session/new`·`session/load`·`session/resume`·`session/fork`·`session/set_mode`·`session/set_config_option`·`session/update`의 모드 변경을 호스트(`AgentOwner`/`NativeRuntime`)와 동기화합니다.
- **설치기 전체 최상위 파일 백업 및 부분 복구 재시도 허용** ([`distribution/ned/installer.nsi`](../distribution/ned/installer.nsi)): 기존에는 `resources`, `locales`, `Ned.exe`만 백업해 최상위 Electron 런타임 파일(`ffmpeg.dll`, `icudtl.dat`, `resources.pak`, `v8_context_snapshot.bin` 등) 추출 실패 시 버전 불일치 위험이 있었고, `resources`만 복구되고 `Ned.exe`가 `.ned-upgrade-backup`에 남은 부분 복구 실패 상태에서는 같은 경로 재시도가 거부됐습니다. `$INSTDIR` 최상위 항목 전체(`.ned-upgrade-backup` 제외)를 하나의 단위로 백업·정리·복구하도록 바꾸고, `CheckInstallDirectory`가 live와 `.ned-upgrade-backup`에 분산된 부분 복구 상태도 재시도 대상으로 허용하도록 고쳤습니다.
- **정적 HTTP 프리뷰 호스트 내장화 및 경계 강제** ([`distribution/data-apps.ts`](../distribution/data-apps.ts)): `python_app_preview(framework: "http")`의 `python -m http.server` 실행을 호스트 내장 Node.js 루프백(`127.0.0.1`) 정적 서버로 전환했습니다. 매 요청마다 원시 경로 세그먼트 검증, `ProjectFiles.resolve()`·`lstat()`·`O_NOFOLLOW` 검사를 적용해 심볼릭 링크·NTFS junction·경로 이탈(`../`, `%2e%2e`)과 `.git`·`.ned`·`.opencode`·`.venv`·`node_modules`·`.env*`·키 파일 및 디렉터리 목록 노출을 차단합니다. `GET`/`HEAD`만 허용하며 Python 가상환경이 없는 정적 프로젝트에서도 동작합니다.
- **OpenViking 0.5.5 자동 기억 종료 레이스 제거 및 Phase 1/2 상태 정리** ([`src/main/session-memory.ts`](../src/main/session-memory.ts), [`src/main/openviking.ts`](../src/main/openviking.ts)): 앱 종료 시 `onSessionDisconnected`가 OpenViking 종료 직전에 강제 `/commit`을 보내던 레이스를 막고, 연결 해제 시에는 완료 메시지만 동기화해 `uncommittedTurns`를 보존하도록 변경했습니다(세션 전환과 다음 실행의 `flushPendingCommits()`에서 커밋). 또한 OpenViking 0.5.5의 Phase 1 아카이브 생성·버퍼 비움 동작에 맞춰 `commitMemorySession`이 `skipped`/`reason`/`archiveUri`를 구분 반환하도록 확장하고, Phase 2 백그라운드 추출 실패 시 빈 버퍼에 `/commit`을 재호출해 `skipped` 응답을 성공으로 오집계하던 루프를 제거했습니다. 사이드카 재시작 후 `not_found`(`404`)가 발생하면 잔류 재시도 카운터를 정리하고 `commitsUnconfirmed`와 `OV_MEMORY_TASK_NOT_FOUND` 진단을 기록합니다.
- **전문 도구 이어하기 정렬 및 컴팩션 프롬프트 건너뛰기** ([`src/main/skill-routing.ts`](../src/main/skill-routing.ts), [`distribution/native-control.ts`](../distribution/native-control.ts)): `previousSessionAnchor`와 `hideUnrequestedTools`가 내부 컴팩션 요약 프롬프트를 건너뛰도록 수정하고, `desktop_`, `document_write`, `diagram_`, `api_`, `worktree_` 5개 전문 도구군이 취소(`interruptSession`)·재연결·연속 이어하기 턴에서 `ModelGateway`와 `HostTools`가 동일한 앵커 요청을 공유하도록 맞췄습니다.
- **다중 파일 크래시 복구 저널 및 편집 직렬화** ([`src/main/files.ts`](../src/main/files.ts), [`distribution/host-tools.ts`](../distribution/host-tools.ts), [`distribution/ast-audit.ts`](../distribution/ast-audit.ts), [`distribution/checkpoints.ts`](../distribution/checkpoints.ts), [`distribution/worktree-sandbox.ts`](../distribution/worktree-sandbox.ts), [`distribution/spec-workflow.ts`](../distribution/spec-workflow.ts), [`distribution/native-control.ts`](../distribution/native-control.ts)): `ProjectFiles.applyBatch`가 원본 본문 없이 대상 경로·스냅샷 ID·적용 상태만 담은 경량 저널(`batch-journals/<id>.json`)을 원자적으로 기록하고, 정상 완료·정상 롤백 시 삭제하며 크래시(`in_progress`)·롤백 실패(`rollback_failed`) 시 보존합니다. 앱 시작 시 미완료 저널을 탐지해 파일을 자동 덮어쓰지 않고 `batch-recovery-status.json`과 `status().incompleteBatches`로 노출합니다. `ast_search(apply: true)`의 자동 체크포인트 시점을 사용자 승인 후로 옮기고, 다중 파일 쓰기 도구(`project_checkpoint(restore)`, `worktree_sandbox(apply)`, `spec_workflow(init)`, `ast_search(apply)`)를 단일 파일 편집과 동일한 `editQueue`로 직렬화했습니다.

## 다음 교차 검토 우선 항목

- **미완료 배치 저널의 UI/복구 도구 노출**: 현재 `batch-recovery-status.json`으로 진단 기록과 스냅샷 ID를 보존하지만, 사용자가 트레이 메뉴나 명시적 도구로 미완료 배치 스냅샷을 조회·정리하는 흐름은 후속 보완 대상입니다.
- **공유 `worker` 하위 에이전트와 다중 파일 도구 간 쓰기 경로 예약 검증**: 현재 `Subagents.scope`의 쓰기 경로 충돌 검사는 `propose_edit`/`patch_file`/`delete_file`에 한정되어 있으므로, 공유 모드 `worker`가 실행 중일 때 부모의 `ast_search(apply)`·`worktree_sandbox(apply)`·`project_checkpoint(restore)` 대상 파일과 예약 경로가 겹치는지 사전 차단하는 보강을 검토할 수 있습니다.
- **실제 직원 PC Windows 10/11 GUI 및 사내 실서버 수용 검증**: Linux 단위/통합 테스트와 Windows Server 2022 오프라인 설치·부분 복구 스모크는 자동화 검증 범위이며, 실제 직원 PC GUI(트레이·Zed 편집기·OpenViking Studio·사내 대기열 모델·실제 사내 PyPI 미러)는 현장 수용 확인이 필요합니다.
