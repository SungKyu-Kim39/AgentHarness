# Ned 제품 요구사항

이 문서는 사용자 지정 변경을 반영한 현재 기준이다. 최종 제품명은 **Ned**이며, OpenCode Desktop 화면을 사용하던 L-Vibe 0.2.x의 전환 기록은 과거 검증 문서에 남긴다.

- 목적: 비개발자를 포함한 직원이 개별 도구를 설치·배선하지 않고 사내 AI 기반 바이브 코딩을 사용하는 통합 환경을 제공한다.
- 배포: ASCII 이름의 TGZ 한 개 → 일반 사용자용 Windows x64 설치 EXE → 중앙 JSON 편집 → 실행의 흐름을 제공한다.
- 화면: Zed에서 코드 직접 편집·저장·탐색을 수행하고 ACP 대화에서 전용 OpenCode 엔진을 사용한다. 별도 엔진을 이중 기동하거나 개인 설정을 읽어 연결하지 않는다.
- 이름·자산: Ned 실행기·설치기·트레이에 검은 배경과 흰색 볼드 Ned 글자의 생성 아이콘을 사용한다.
- 설정: OpenCode provider 형식, 여러 LLM의 선택, 단일 임베딩, 정확한 서버 모델 ID, 모델별 한도와 thinking 변형을 지원한다. 키는 safeStorage로 암호화한다.
- 대기: 사내 서버 대기열을 고려하여 모델 응답에 기본 경과 시간 제한을 두지 않는다. 사용자 중지와 상태 확인을 별도로 제공한다.
- 도구: Aegis·Conductor, 기본 스킬 34개, Serena·clangd, OpenViking, Graphify, REA와 선정한 6개 MCP를 고정 오프라인 구성으로 제공한다. 불필요한 전체 스킬 로딩과 도구 선택 확인은 강제하지 않는다.
- 지식: OpenViking을 앱과 함께 기동·종료하고 기본 스킬을 등록한다. 명시적으로 가져온 개인 지식은 해당 사용자의 모든 프로젝트에서 읽는다. 새 대화 자동 업로드와 공용 저장소 자동 연결은 하지 않는다.
- 승인: 선택한 프로젝트 읽기·검색은 자동이다. AI 수정과 빌드 등 실행은 승인한다. 메모리의 자동 승인 범위는 실제 사용자 요청·세션·프로젝트에 묶고 새 요청·중지·재실행에서 해제한다.
- 수동 편집: 사용자의 직접 저장은 승인 없이 수행한다. AI 쓰기 직전과 승인 이후 저장되지 않은 버퍼·디스크 변경을 확인한다.
- 빌드: 설치된 VS2017/2019 MSBuild와 솔루션 구성을 탐색한다. 실행 파일·인자·작업 폴더·환경·대상을 고정하고 승인 뒤 다시 검사한다. SDK 자동 설치·retarget·임의 셸 문자열 해석은 하지 않는다.
- 종료: 승인된 명령은 Windows Job Object가 소유하며 자식 종료를 확인한다. 종료가 불명확하면 새 실행을 차단한다.
- 오프라인: 업데이트·텔레메트리·원격 스킬·최초 LSP 다운로드를 막는다. 직원 PC에서 패키지 설치를 수행하지 않는다. 설정만으로 완전 차단을 입증했다고 주장하지 않는다.
- 보존: Ned 전용 설치·데이터 경로를 사용한다. 기존 L-Vibe 원본을 보존하여 이관하고 기존 Ned 설정·데이터를 덮어쓰지 않는다.
- 라이선스: 자체 코드와 각 구성 요소의 조건을 구분하고 Zed GPL 대응 소스와 고지를 포함한다.
- 출시: 합성 모델·Linux 검사·EXE 생성과 Windows 실제 설치·사내 모델·SDK·DNS/TCP 검증을 구분한다.

구현 경계는 [아키텍처](architecture.md), 실제 확인 범위는 [0.3.0 검증 상태](validation-0.3.0.md), 남은 수용 항목은 [Windows 검증](windows-acceptance.md)을 따른다.
