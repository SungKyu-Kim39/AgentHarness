# L-Vibe 설계 기준

사용자가 나누어 제공한 1~10절을 구현 기준으로 통합했다. 원문의 제품명 `LIG Agent`는 사용자 우선 지시에 따라 `L-Vibe`로 변경한다. 로고의 `LIG` 표기는 유지한다. 원문에 기재된 이전 후보의 구현·검토 결과는 이번 저장소의 검증 결과와 구분한다.

## 1. 범위

- 제품 기준은 사용자의 개발 요청서다. 기존 개발본은 제공되지 않았다. 기존 PC의 OpenCode·Zed·개인 플러그인·설정을 읽거나 복제하지 않는다.
- Windows 10·11 x64, 외부 인터넷 차단, 사내 모델 API 연결을 전제로 한다.
- 1.0 범위는 프로젝트 코드 분석·수정과 개발 문서 작성이다. 화면 조작·Agent Desktop은 제외한다. Office/PDF 전용 편집은 미확정이다.
- 공용 지식은 확장 인터페이스로 남긴다. 개인 대화 자동 업로드는 하지 않는다.
- 0.1은 설정·엔진·승인·반복 출력 기반 검증 단계다. 목표 구성의 미구현 항목을 검증 보고서에 명시한다.

## 2. 목표 구성과 보안

Electron UI → 타입·출처 검사 IPC → 앱 호스트 → 승인·범위·중지 정책 → 앱 전용 OpenCode → 지정된 사내 모델 API 및 통제된 도구 중계로 구성한다. 호스트가 엔진 수명·설정·승인·이벤트·사용자 기록을 소유한다. Aegis/Conductor는 호스트 어댑터, Serena/고정 clangd는 승인 경계 안의 의미 탐색 인터페이스로 연결한다. 답변 재작성기는 실행 엔진과 분리한다.

- 외부 OpenCode UI·설치 상태·공유 서버 자동 검색을 사용하지 않는다. 모델 가중치는 EXE에 포함하지 않는다.
- 렌더러에 Node·파일·모델 API·엔진 자격증명을 노출하지 않는다. contextIsolation, sandbox, 제한 preload, CSP, 탐색·팝업 차단을 적용한다.
- 엔진은 127.0.0.1 임의 포트와 실행별 자격증명을 사용한다.
- 프로젝트·전역 플러그인이 앱 정책을 덮어쓰지 못하게 구성한다. 설정 파일만으로 모든 직접 I/O가 통제된다고 간주하지 않는다.

## 3. 화면

- 왼쪽: 네이비 정사각형 흰색 굵은 LIG 로고, 프로젝트, 최근 대화, 새 작업, 모델 설정.
- 중앙: 요청·답변, 작업 예정 계획과 실제 도구 성공의 구분, 도구 이벤트, 승인 카드, 필요한 사용자 결정, 하단 입력창.
- 도구 카드: 호출 ID·도구·대상·대기/승인 대기/실행 중/성공/실패·확인된 결과.
- 오른쪽: 파일 목록·변경 비교. 승인 전 제안·대상 경로, 승인 후 실제 결과. 제안 이후 외부 변경 시 재확인. Git 없이 호스트 스냅샷으로 비교.
- 0.1: 엔진이 전체 내용을 제공하면 전체 비교, 패치면 해당 구간 비교와 실제 엔진 도구 상태. 독립 계획 카드·정교한 줄별 diff·세션 전체 스냅샷 비교는 후속 범위.
- Codex의 배치·흐름을 참고하되 제품명·자산은 독립 구성한다.

## 4. 설치 A와 설정 보존

기본 경로는 `%LOCALAPPDATA%\Programs\L-Vibe`, 데이터는 `%APPDATA%\L-Vibe`다. 일반 사용자 설치이며 관리자 권한을 요청하지 않는다.

1. 저장된 사용자 설정이 있는지 확인한다.
2. 최초 설정이 없을 때 설치기의 `$EXEDIR\agent-config.json`을 사용자 폴더 임시 가져오기 파일로 복사한다. CWD·설치된 앱 EXE 옆을 원본으로 사용하지 않는다.
3. 첫 실행에서 JSON 문법·필수 필드·URL을 검증한다. 오류 원인과 파일 가져오기를 제공한다.
4. 키를 Electron safeStorage의 Windows 사용자 보호 기능으로 암호화한다. 성공 후 준비 평문만 삭제한다. 복호화 실패 시 평문 저장으로 전환하지 않는다.
5. 이후 실행·업데이트는 저장 복사본만 사용한다. 파일 선택과 명시적 교체만 설정을 변경한다.

원본 배포 JSON과 설치~첫 실행 사이의 준비 파일은 평문이다. Windows 검증에 두 폴더의 ACL 확인을 포함한다. 키는 UI·앱 로그·지원 내보내기에 넣지 않는다. 엔진 자체 진단 파일까지 비밀 누출 검증을 수행해야 한다.

스키마 v1은 `schemaVersion: 1` 및 `model.baseUrl/apiKey/id`다. baseUrl은 OpenAI 호환 기준 경로(`/v1` 등)이며 `/chat/completions`를 앱이 붙인다. ID를 모델 표시명에서 유추하지 않는다. 키를 소스·EXE에 포함하지 않고 모델 목록을 조회하지 않는다.

보수적 context/output 한도는 32768/4096이다. Qwen3.8-27B의 확인된 사양이 아니며 실제 서버 한도·reasoning 필드·tool call을 확인한 뒤 1.0 스키마에 반영한다.

설정·대화 DB는 설치 디렉터리 밖에 두고 업데이트·제거 시 기본 유지한다. 손상·다른 사용자의 복호화 실패는 자동 덮어쓰기 사유가 아니다. DB 마이그레이션은 백업·버전 검사·실패 복구를 포함해야 한다.

## 5. 폐쇄망 번들

고정 Windows x64 Electron·OpenCode 및 필요한 라이브러리를 포함한다. Git/MinGit·셸은 앱 전용 PATH, ripgrep·Python·완성된 site-packages·Serena tools MCP·clangd와 DLL·필요한 언어별 LSP를 빌드 시 확보하고 경로·해시·라이선스를 고정한다. Aegis 본체·Conductor 스킬/템플릿과 어댑터를 포함한다. Bun/별도 Node는 외부 실행기 필요성을 확인한 뒤 결정한다.

원문 후보는 Electron 45.2.3·OpenCode 1.19.5이며 Git/셸·Python·clangd는 미포함, 명령은 차단 상태였다. 이 설명은 이번 구현의 완료 근거로 쓰지 않는다.

- 직원 PC에 npm/pip/uvx/bun install/git clone 설치 경로를 제공하지 않는다.
- 빌드 PC의 Python 가상환경을 그대로 복사하지 않는다. Windows 패키지·DLL·경로로 구성한다.
- 앱·엔진·플러그인 업데이트, models.dev, 외부 인증, 원격 스킬, LSP/토크나이저 최초 다운로드, 텔레메트리, 웹 검색/fetch/공유를 금지하거나 제거한다.
- 환경 변수만으로 폐쇄망 보장을 주장하지 않는다. 설치~재시작의 실제 DNS·TCP를 관찰한다.

## 6. 기본 연동과 자연어 선택

원본은 Serena `https://github.com/oraios/serena`, Aegis `https://github.com/GanyuanRan/Aegis`, Conductor `https://github.com/gemini-cli-extensions/conductor`다. 커밋·배포 사용 여부는 vendor-lock.json에 기록한다.

### Serena

원문 검토 버전은 2.1.1.dev0이다. 제한된 tools 인터페이스와 명시적 도구 목록을 사용한다. REPL은 목록 제외만으로 수정·실행을 막을 수 없으므로 기본 제공하지 않는다.

정의·참조·호출 영향은 find_symbol/find_referencing_symbols/심볼 개요의 실제 결과로 판단한다. 실패 시 텍스트 검색 대체를 표시하고 의미 분석 성공으로 기록하지 않는다. C++ ls_path를 번들 clangd 절대 경로로 지정하고 관리형 다운로드·dashboard/GUI·activation command를 차단한다. 프로젝트의 임의 LSP/REPL/실행 설정을 신뢰하지 않는다.

compile_commands.json을 사용하고 include·매크로·옵션·VxWorks SDK 헤더 부족의 정확도 제한을 밝힌다. 독점 SDK·모델 가중치를 임의 번들하지 않는다.

### Aegis

원문 검토 버전은 2.15.0이다. Bun 온라인 Git 설치와 캐시 상태의 원격 HEAD 확인 경로를 직원 PC에서 사용하지 않는다. 필요한 원본 지침을 읽는 어댑터를 우선한다. 네이티브 플러그인이면 업데이트·직접 I/O를 검토·제거하고 변경을 기록한다. 스킬 복사로 complete install/doctor 통과를 주장하지 않는다.

넓은 영향·여러 파일·긴 작업은 현재 상태·기준 조사 → 계획 → 변경 → 검증 근거를 남긴다. 작은 요청에는 문서·트랙·전체 스킬을 강제하지 않고 도구 선택의 별도 동의를 요구하지 않는다.

### Conductor

원문 검토 버전은 0.3.0이다. Gemini 설치 명령을 실행하지 않고 원본 스킬·템플릿·트랙 문서를 호스트 도구에 매핑한다. 공식 OpenCode 네이티브 플러그인 설치로 표현하지 않는다.

conductor/index.md·tracks.md와 관련 spec/plan을 읽고 관련 트랙을 우선 이어간다. 여러 트랙 선택이 제품 범위를 바꾸면 실제 작업 내용으로 질문한다. 새 트랙은 필요한 경우만 만든다. 진행·체크박스 갱신에는 실제 실행·검증 근거가 필요하고 파일 수정 승인을 거친다. 매번 확인/Q&A 루프가 제품 요구와 충돌하면 사용자 요구를 우선하며 어댑터에 변경점을 기록한다.

VxWorks→Windows 포팅 예에서는 저장소·대화·기존 트랙 조사, 실제 의미 탐색, 영향·계획·검증, 관련 트랙의 조합을 사용한다. VxWorks 유지 여부가 미결이면 사용자에게 물으며 의존 변경은 보류하고 독립 읽기는 계속한다. 자동 승인은 이 결정의 답이 아니다. 규모·실패로 전제가 바뀌면 절차를 재선택하며 키워드·계획의 플러그인 이름만으로 통합 성공을 판정하지 않는다.

## 7. 승인 경계

- 프로젝트 내부 읽기·검색 자동, 수정·명령 승인, 범위 밖·알 수 없는 효과 기본 차단.
- 세션 자동 승인은 메모리에만 두며 엔진 always 승인을 저장하지 않는다. 재실행·세션/프로젝트 전환 시 해제한다.
- Serena 등 MCP도 읽기/수정/명령 분류 중계를 거친다. 동일 파일을 다른 도구로 바꾸어도 승인 생략 금지. Serena는 읽기/의미 탐색, 변경은 호스트 도구로 통일하는 방식을 우선한다.
- Node/Python 실행 플러그인의 직접 쓰기·프로세스 생성을 엔진 이벤트만으로 통제한다고 보지 않는다. 검토한 순수 지침·통제 어댑터만 기본 제공하며 임의 서드파티 플러그인 설치를 제공하지 않는다.
- 명령 승인 시 실행 파일·인자·CWD·환경·대상을 고정한다. 셸 재해석·승인 후 대상 변경 금지. Windows Job Object 등으로 자식 종료를 확인한다. 종료 미확인 시 새 실행·재출력 차단. 0.1은 명령 미허용.

## 8. 반복과 답변 재출력

검사 대상은 assistant 사용자용 텍스트뿐이다. reasoning·tool output·사용자 입력은 제외한다. Markdown fence·들여쓴 코드를 제외하고 공백·문장부호 정규화 후 12자 이상 문장이 최근 20문장 중 4회, 또는 6~160자 구절이 5회 연속이면 감지한다. 실제 모델 자료로 임계값을 조정해야 한다.

상태: idle → running → stopping → stopped 또는 unconfirmed. unconfirmed는 중지 재확인만 허용한다. stopped에서 사용자 요청으로 replaying → stopped다. 중지 요청과 확인을 구분하고 abort·idle·실행 도구/자식 없음 확인 전 재출력 금지. 자동 재출력 금지.

재출력기는 같은 대화의 요청·완료된 도구 결과를 읽고 모델에 답변만 요청한다. prompt_async/MCP/명령과 분리하고 도구 정의를 보내지 않으며 tool_choice=none을 지정한다. 반환된 tool/function call은 실행 없이 오류 처리한다. 정상 답변은 원래 호스트 세션 ID 아래 별도 저장한다.

0.1 문맥은 최근 40개 사용자 요청·완료 도구 결과, 항목별 길이 제한이다. 긴 작업 결정·이전 확정 답변·큰 결과를 보존하는 영속 요약 스냅샷과 도구 호출만 반복되는 루프 예산은 후속 정책이다.

## 9. 저장과 공용 지식

설정·엔진 DB/이력·프로젝트 목록·재출력은 사용자 데이터, Conductor 등 산출물은 프로젝트 안에 둔다. 개인 대화와 공용 지식 커넥터의 저장소·승인·보존을 분리한다. 향후 관리자 지정 사내 endpoint의 읽기 인터페이스를 우선한다. OpenViking·Graphify·개인 스킬 약 200개는 기본 번들로 결정되지 않았다.

## 10. 순서와 출시 조건

1. Windows 실행기에서 일반 사용자 Win10/11 설치·첫 실행·업데이트 검증.
2. 전체 Windows 런타임 고정과 실제 네트워크 관찰로 최초 다운로드 제거.
3. Serena read-only MCP/clangd의 C++ 정의·참조·호출 영향과 실패 대체 검증.
4. Aegis/Conductor 자연어·기존 트랙·범위 확대·사용자 결정의 실제 호출 검증.
5. 명령 승인·자식 종료·스냅샷 diff·마이그레이션 구현.
6. 외부 차단/시험 모델만 허용한 VM과 실제 사내 Qwen 서버에서 전체 수용 검증.

설치 EXE·단위 테스트·합성 서버 통과만으로 1.0 완료 처리하지 않는다. 검증마다 OS·빌드 해시·모델 endpoint 종류·명령·관찰 결과를 남긴다.
