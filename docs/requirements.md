# Ned가 해결하려는 문제와 제품 요구사항

Ned는 개발 도구를 직접 설치·연결하기 어려운 직원도 사내 AI로 코드와 문서를 다룰 수 있도록 만든 통합 환경입니다. 현재 제품 이름은 **Ned**이며, OpenCode Desktop을 사용하던 L-Vibe 0.2.x의 변경 이력은 과거 검증 문서에 남겼습니다.

## 설치와 화면

배포는 ASCII 이름의 TGZ를 반입해 EXE를 설치하고 중앙 JSON을 설정한 뒤 실행하는 순서입니다. 대상은 일반 사용자 계정의 Windows x64입니다. 실행기·설치기·트레이에는 검은 배경의 흰색 굵은 Ned 아이콘을 사용합니다.

코드 탐색·직접 편집·저장은 Zed에서 하고, ACP 대화에는 전용 OpenCode 엔진을 연결합니다. 개인 설정이나 기존 엔진을 읽어 붙이지 않으며 엔진을 중복 실행하지 않습니다. 수동 저장은 승인 없이 할 수 있고 AI 쓰기 전에는 미저장 버퍼와 디스크 변경을 확인합니다.

## 모델과 도구

OpenCode provider 형식의 중앙 JSON으로 여러 LLM을 등록·선택합니다. 임베딩은 한 개를 지정하며 서버 모델 ID와 모델별 한도·thinking 변형을 정확히 전달합니다. 키는 `safeStorage`로 암호화합니다. 사내 서버 대기열을 고려해 모델 응답에 기본 경과 시간 제한을 두지 않고, 사용자 중지와 서비스 상태 확인을 따로 제공합니다.

Aegis·Conductor, 기본 스킬 66개, Serena·clangd, OpenViking, Graphify, REA와 개발 MCP 6종을 고정 오프라인 구성으로 제공합니다. 필요한 지침만 읽고 도구를 고를 때마다 동의를 묻지 않습니다. 요청·대화 문맥에 맞는 지침 선택은 0.3.7에 포함됩니다.

VS2017/2019가 있으면 MSBuild와 솔루션 구성을 조사합니다. 실행 파일·인자·작업 폴더·환경·대상을 고정해 승인 후 다시 확인합니다. SDK 자동 설치·retarget이나 임의 셸 문자열 실행은 하지 않습니다. Windows Job Object가 명령의 자식을 관리하며 종료가 확인되지 않으면 새 실행을 막습니다.

## 권한과 지식

승인한 프로젝트의 읽기·검색은 자동 처리합니다. AI 수정·빌드·지식·데스크톱은 호스트 권한 정책을 따릅니다. 사용자는 승인 요청·프로젝트 파일 자동 승인·전체 권한을 선택하고 업데이트 후에도 유지할 수 있습니다. 승인창에서 받은 임시 요청·대화·프로젝트 허용은 해당 범위와 중지·재시작 조건에 맞게 해제합니다. 제품 방향을 결정하는 질문은 권한 설정과 구분합니다.

OpenViking은 앱과 함께 실행·종료하고 기본 스킬을 등록합니다. 명시적으로 가져온 개인 지식은 같은 사용자의 모든 프로젝트에서 읽습니다. 새 대화를 자동 업로드하거나 공용 저장소를 자동 연결하지 않습니다.

## 배포와 검증

직원 PC에서 패키지 설치, 자동 업데이트, 텔레메트리, 원격 스킬과 첫 LSP 다운로드를 요구하지 않습니다. 실제 외부 통신 차단은 설정 검토와 별도로 DNS·TCP를 관찰해 확인합니다.

설치·데이터 경로는 Ned 전용으로 사용합니다. L-Vibe 원본을 남겨 이관하고 기존 Ned 설정·자료는 덮어쓰지 않습니다. 자체 코드와 번들별 라이선스를 구분하며 Zed GPL 대응 소스와 고지도 제공합니다.

검증 결과는 환경별로 기록합니다. 합성 모델·Linux 연동·설치 파일 생성, Windows Server 검사와 직원 PC의 실제 Windows·사내 모델·SDK·네트워크 검증을 합산해 완료로 판단하지 않습니다. [아키텍처](architecture.md), [0.3.7 검증 결과](validation-0.3.7.md), [Windows 확인 항목](windows-acceptance.md)에 구현과 남은 검사를 정리했습니다.
