# Ned의 서브에이전트 사용

0.3.8 rebuild1부터 Ned Agent는 큰 작업의 일부를 별도 Agent에게 맡길 수 있습니다. 예를 들어 한 Agent가 기존 함수와 참조 관계를 조사하는 동안 다른 Agent가 할당받은 파일을 수정합니다. 주 Agent는 돌아온 결과를 검토하고 최종 빌드·검증과 답변을 담당합니다. 스킬을 여러 개 읽는 것과 달리 실제로 독립된 모델 대화가 실행됩니다.

## 언제 사용하는가

“이 저장소의 오류를 조사하고 수정한 뒤, 영향받는 부분을 따로 검토해 줘”처럼 조사·구현·검토를 나눌 수 있는 요청에 적합합니다. Ned는 요청 내용과 작업 규모를 보고 위임 여부를 판단합니다. 사용자가 “조사와 구현을 하위 Agent로 나눠 진행해 줘”라고 직접 요청할 수도 있습니다. 짧은 질문이나 한 줄 수정에 매번 하위 Agent를 만드는 방식은 아닙니다.

주 Agent가 조사 범위와 필요한 배경을 전달합니다. 하위 Agent는 부모 대화 전문을 자동으로 읽지 않으므로, 요청에 빠진 전제나 사용자 결정을 대신 추측해서는 안 됩니다. 같은 모델과 프로젝트를 사용하며 새로운 외부 서비스나 계정은 필요하지 않습니다.

## 역할과 권한

| 역할 | 할 수 있는 작업 | 담당하지 않는 작업 |
| --- | --- | --- |
| 조사 Agent | 파일·심볼·Git 상태·스킬·지식 읽기, 지원하는 정적 분석과 검토 | 프로젝트 수정 |
| 구현 Agent | 조사 도구 사용, 지정받은 정확한 파일의 수정·삭제 제안 | 지정하지 않은 파일의 변경 |
| 주 Agent | 작업 분배, 결과 통합, 빌드·Python 실행·Git 변경·데스크톱 조작, 사용자 결정 확인 | 확인하지 않은 결과를 성공으로 보고하는 행동 |

하위 Agent도 현재 부모 대화의 Ned 권한 설정을 따릅니다. 수정 승인과 미저장 편집 버퍼·외부 변경·스냅샷 검사는 그대로 적용됩니다. 전체 권한에서 허용하는 외부 파일 읽기도 같은 규칙을 따릅니다. 하위 Agent에게 파일을 맡겼다는 이유로 새로운 실행 권한이 생기지는 않습니다.

구현 작업은 프로젝트 상대 경로로 정확한 파일 목록을 지정합니다. 같은 프로젝트에서 진행 중인 하위 작업끼리 수정 파일을 겹치게 맡길 수 없습니다. 그 파일은 하위 작업이 끝나거나 중지될 때까지 주 Agent의 수정에서도 제외합니다. 독립적으로 나누기 어려운 변경은 주 Agent가 순서대로 처리하는 편이 적합합니다. 하위 Agent의 재위임은 지원하지 않습니다.

## 진행 상태와 결과

Ned 전체에서 동시에 실행되는 하위 Agent는 최대 두 개입니다. 추가 작업은 대기하며 실행·대기를 합쳐 최대 32개까지 접수합니다. 사내 모델 서버의 대기열에 들어간 상태는 완료가 아닙니다. 모델 생성 자체에 임의의 기본 시간 제한을 두지 않습니다. 위임으로 모델 요청 수가 늘어나므로, 서버가 혼잡할 때는 병렬 실행이 더 빨라진다고 보장할 수 없습니다.

`ned_host_spawn_subagent`는 작업 ID를 반환합니다. 완료·실패 결과는 원래 부모 대화로 자동 전달되며 주 Agent가 확인된 결과를 통합합니다. `ned_host_subagent_status`로 최근 50개 작업의 상태를 확인할 수 있습니다. 작업 ID를 지정하면 결과를 최대 32,000자씩 조회하고 `nextOffset`으로 이어 읽습니다. 결과 알림의 요약 범위를 넘는 내용은 이 조회로 확인합니다. 응답이 오지 않는 동안 상태를 계속 반복 조회할 필요는 없습니다.

도구 카드에 `queued`·`running`이 나타나면 아직 성공한 것이 아닙니다. `completed`는 하위 작업의 실행 완료를 뜻하며, 제품 전체 빌드나 최종 수용까지 완료했다는 의미는 아닙니다. 주 Agent가 각 결과의 근거와 남은 검증을 구분해 보고합니다.

## 중지·재시작

사용자가 대화를 중지하거나 새 요청을 보내면 이전 요청의 하위 작업도 중지하고 확인합니다. `ned_host_stop_subagent`로 특정 작업만 중지할 수도 있습니다. 엔진의 중지를 확인하지 못하면 해당 부모 대화의 새 작업을 보류합니다. 대화 연결 해제나 Ned 종료 때도 소유한 하위 작업을 정리합니다.

Ned는 작업 ID·역할·상태 등의 접수 기록을 사용자 데이터 폴더의 `subagents.json`에 보존합니다. 하위 대화 본문은 엔진의 개인 작업 DB에 남으며, 별도 접수 기록에 프롬프트와 결과 전문을 중복 저장하지 않습니다. 재시작 시 미완료 기록의 실제 엔진 소유권을 확인하고 중지합니다. 이전 기록만으로 하위 Agent를 자동 재실행하거나 수정 권한을 복원하지 않습니다.

## 기본 Zed Agent와의 구분

이 기능은 Ned ACP와 번들 OpenCode의 실제 하위 세션을 Ned 호스트가 관리하는 방식입니다. 제한 없는 OpenCode 명령 실행기나 임의 플러그인을 노출하지 않습니다. 기본 Zed Agent를 선택하면 Zed 자체 `spawn_agent`와 자체 권한 체계를 사용하며 이 Ned 하위 작업 서비스에 연결하지 않습니다. 두 경로는 [Agent 선택 안내](zed-native-agent.md)에서 비교할 수 있습니다.
