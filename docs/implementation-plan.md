# Ned 구현과 수용 순서

1. **구현·Linux 연동 확인:** Ned 이름·생성 아이콘, 전용 Zed 프로필, 기존 호스트 엔진에 연결하는 ACP, 실제 모델 목록·대화·승인 수정, 저장하지 않은 버퍼 보호.
2. **구현·제어 검사:** 기존 L-Vibe 설정·기록 보존 복사, VS2017/2019 탐색과 고정 MSBuild 승인·입력 재검사·Job 소유 실행. 실제 Windows 실행은 별도 확인한다.
3. **패키지 준비:** 고정 Zed Windows 바이너리·원본 소스·고지, 기존 오프라인 런타임과 34개 스킬을 단일 Ned 설치기로 결합한다.
4. **Windows 수용:** 일반 사용자 설치·설정·이관·수동 저장·ACP 모델 전환·실제 MSBuild와 중지·OpenViking 등록·검색·재시작을 확인한다.
5. **폐쇄망 수용:** 실제 DNS/TCP와 최초 다운로드 의존, 실제 사내 Qwen·BGE API, SDK 있는 C++ 프로젝트를 확인한다.
6. **후속 기능:** v2 반복 탐지·검증된 중지·수동 답변 재출력, 세션 전체 스냅샷 비교, 장기 대화 결정의 영속 정리를 구현한다.

버전·해시·명령·관찰 결과를 기록하고 완료 여부를 증거와 연결한다. 실제 Windows 검증이 없으면 `releaseReady: false`를 유지한다.
