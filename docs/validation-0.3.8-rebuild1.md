# Ned 0.3.8 수정 빌드 1 검증 기록

이번 수정 빌드는 기본 Zed Agent 선택, Ned 메뉴·About 화면, Astryx UI 스킬과 오프라인 시작 프로젝트, Ned 서브에이전트를 추가합니다. 앱의 기본 버전은 0.3.8로 유지하고 파일명과 빌드 기록을 rebuild1으로 구분합니다. 이미 공개한 0.3.8 EXE·TGZ·태그는 보존합니다.

## 두 Agent의 경계

기본 Zed Agent는 별도의 로컬 모델 중계에 연결합니다. 실제 사내 키 대신 실행별 토큰을 Zed 프로세스에 전달하며, JSON에는 공개 모델 목록과 로컬 주소만 기록합니다. 같은 wire ID를 가진 여러 제공자를 별도 모델 별칭으로 구분합니다. 모델 주소·인증·기본 요청 옵션을 공유하되 Ned 도구·스킬·MCP·OpenViking·요약 재시도 지침은 주입하지 않습니다. Zed 자체 도구와 권한 체계를 사용하며 웹 검색·fetch와 임의 MCP 자동 연결은 폐쇄망 설정에 따라 끕니다.

로컬 합성 서버에서 제공자별 실제 주소·키 선택, 메시지·도구 정의 보존, 요약 length 응답 무변경, 잘못된 토큰·모델·외부 주소·다른 localhost 포트 차단, 대기 중 사용자 취소와 종료 후 포트 정리를 확인했습니다. UI 글꼴·패널과 유효한 기본 모델·프로필 선택 보존도 검사했습니다. 실제 사내 Qwen과 직원 PC의 Zed 기본 Agent 대화는 별도 확인 항목입니다.

## 메뉴와 About

Zed 1.28.1 고정 소스의 두 Rust 파일과 Ned About 이미지를 수정합니다. 메뉴는 Ned·About Ned·Quit Ned로, About은 Ned 0.3.8 rebuild1과 제품 설명·Ned 아이콘으로 표시합니다. 기반 Zed 버전과 소스 정보도 유지합니다. 시작·종료 로직은 바꾸지 않았음을 원본 파일의 수정 범위 비교로 검사했습니다.

Windows 원본 소스 빌드: [43966924528](https://github.com/SungKyu-Kim39/AgentHarness/actions/runs/43966924528). 소스 빌드를 완료했으며 커밋 0b05464에 바이너리·대응 소스·빌드 기록을 고정했습니다. 편집기 EXE는 264,049,664 bytes, SHA-256 92de91ba362d7597e56aa3a3ae30ff9cc684a2077c0eb9a94c96239e130ca8c5입니다. 새 설치본의 GUI 수용과는 구분합니다. 수정 대응 소스는 TGZ의 source/에 보존합니다. 설치 폴더에는 작은 변경 기록과 위치·해시 안내만 두고 소스 아카이브를 중복 설치하지 않습니다.

## Astryx

Astryx Core/CLI 0.7.16의 참조 자료 281개를 정적 문서로 제공하고 기본 스킬을 67종으로 늘립니다. 원본 CLI는 실행하지 않습니다. 별도 Windows x64 시작 프로젝트 ZIP은 React 19.2.0, Core, 일곱 가지 테마, StyleX, esbuild 0.25.12와 잠근 의존성을 포함합니다. 설치 시에는 ZIP 한 파일로 보관하므로 node_modules의 1만여 파일을 설치 폴더에 전부 풀지 않습니다.

Linux의 동등 버전 esbuild로 시작 프로젝트를 빌드하고 Chromium에서 실제 Astryx Button 클릭 후 횟수가 1로 바뀌는 것을 확인했습니다. 해당 실행의 외부 요청은 0건, JavaScript 오류는 0건이었습니다. 이 결과는 Windows 실행 검증과 구분합니다. Windows 설치본에서는 동봉 Windows esbuild로 기존 dist를 삭제한 뒤 실제 재빌드하는 검사를 추가했습니다.

모든 스킬을 호스트로 읽는 검사, 실제 OpenCode의 67종 스킬 검색, 변조·경로 이탈 거절이 통과했습니다. 추가 ZIP의 경로 10,352개는 ASCII이며 Windows 실행 파일 포함과 Linux 실행 파일 미포함을 확인했습니다. Astryx 및 각 의존성의 라이선스·저작권·해시와 package-lock을 유지합니다.

## 검증 진행 상태

TypeScript와 호스트 빌드, 스킬 67종 무결성 검사를 통과했습니다. 최신 Linux 전체 회귀는 211건 중 199건 통과·12건 환경별 제외·실패 0건이며 690.850초가 걸렸습니다. 실행 명령은 `ELECTRON_BUILDER_CACHE="$PWD/.cache/ned/builder-cache" npm test`입니다. 서브에이전트 실제 엔진 검사와 소스 편집기 검사도 이 실행에 포함합니다.

초기 전체 실행은 205건 중 스킬 개수를 66으로 가정한 두 검사와 NSIS 캐시 경로 한 건이 실패했습니다. 개수를 67로 갱신하고 고정 도구 캐시를 지정한 뒤 대상 재검사와 위 전체 회귀에서 통과했습니다. 실제 OpenViking 67종 등록·재시작 무중복·프로젝트 범위, 0.5.0 자료 이관, 프로젝트별 Python 환경의 OpenViking 저장·조회도 통과했습니다. 사내 모델 생성에 기본 대기 제한을 추가하지 않았으며 실제 OpenCode의 185초 이상 대기·사용자 중지도 확인했습니다. 새 EXE·TGZ 생성과 Windows 설치 검증은 진행 중입니다.

직원 Windows 10·11, 실제 사내 모델, GUI 레이아웃과 기본 Zed Agent 선택, 외부망 차단 전체 DNS/TCP 관찰은 별도 수용 범위입니다. `releaseReady`는 전체 수용 전까지 false입니다.

## 서브에이전트 확인

Ned 호스트에 spawn_subagent·subagent_status·stop_subagent를 추가했습니다. 실제 번들 OpenCode와 localhost 합성 모델을 사용해 조사·구현 두 하위 세션의 도구 실행, 지정 파일 수정, 부모 승인과 편집 버퍼 검사 상속, 자동 결과 전달과 부모 답변 재개를 확인했습니다. 응답을 보내지 않는 하위 모델 요청도 부모 중지 시 연결이 닫히며 뒤늦게 부모를 깨우지 않았습니다. 이 검사는 실제 사내 모델의 자율 작업 품질을 입증하는 검사는 아닙니다.

단위 검사에서는 세 번째 작업 대기·파일 배정 충돌·미할당 파일 거절·조사 Agent 쓰기와 재위임 거절·부모 요청 변경·소유하지 않은 세션 거절·중지 미확인 차단과 재시도·재시작 기록 복구·접수 도중 취소·긴 결과 분할을 확인했습니다. 단위 4건과 실제 엔진 통합 1건이 통과했습니다. 동시에 두 작업을 접수하는 실제 엔진 검사에서 발견한 접수 완료 전 실행 경쟁은 접수 확정 플래그를 둬 수정했습니다.

제한 없는 OpenCode 기본 subagent·spawn_agent·task 도구는 계속 노출하지 않습니다. 대신 Ned 호스트가 생성·소유한 세션만 역할별 도구와 부모 범위로 실행합니다. 기본 Zed Agent의 spawn_agent는 Zed native 내부 경로이며 Ned의 이 서비스와 연결하지 않습니다. Zed의 하위 GUI 작업 성공은 아직 수용 증거에 포함하지 않습니다.

## Windows의 새 소스·Astryx 검사

[사전 검사 43974417593](https://github.com/SungKyu-Kim39/AgentHarness/actions/runs/43974417593)에서 기본 Zed 모델 연결·설정 유지·대기 취소 3건과 실제 Windows Astryx 재빌드 1건이 모두 통과했습니다. 설치된 기존 0.3.8의 Node를 실행기로 사용하고 새 ZIP·테스트 소스를 별도로 복사한 검사입니다. 새 rebuild1 설치본의 수용 검사로 합산하지 않습니다. 모델은 localhost 합성 서버이며 Ned Node의 Internet 송신은 Windows 방화벽으로 차단했습니다.

첫 사전 검사는 테스트 파일만의 JSONC UMD 번들 누락으로 중단됐습니다. 제품 호스트에서 이미 쓰는 고정 ESM 별칭을 테스트 빌더에도 적용했습니다. 두 번째는 PowerShell 7의 Archive 모듈 경로가 Windows PowerShell 5에 상속되어 지원하지 않는 .NET 오버로드를 호출했습니다. OS 기본 .NET의 두 인자 ZIP API로 바꾸어 세 번째 검사에서 통과했습니다. 이 두 실패를 설치본 결함이나 사내 서버 오류로 분류하지 않습니다.
