# Inherit Legacy Style — Ned development

ECC inherit-legacy-style을 Codex용으로 조정했다. ../../README.md에 출처·변경 정책이 있다. references/upstream.md는 원문 감사 자료다.

1. 대상 파일과 인접 구현, 실제 호출자, 관련 테스트를 읽는다. 프로젝트 전체 조사보다 수정 영역의 관례를 우선한다.
2. 이름, import, 파일 구성, 타입·오류 처리, async/취소, 자원 소유권을 확인한다. 좋은 예시 경로와 관찰한 사실을 짧게 적는다.
3. TypeScript 호스트는 distribution/ned/의 인접 모듈을, 공통 실행은 src/main/을, 패키징은 scripts/ned-*.mjs를 출발점으로 삼되 실제 관련성을 확인한다. 테스트는 tests/의 가까운 사례를 따른다.
4. 대상 파일의 기존 형식과 줄바꿈을 유지한다. 과거 압축된 코드를 손본다는 이유만으로 전체 파일을 재포맷하지 않는다. 명백한 결함이나 보안 문제는 관례로 복제하지 않는다.
5. 관례가 섞여 있으면 해당 모듈의 현재 의도와 도구 설정을 근거로 판단하고 필요한 가정만 설명한다. 동작·호환성이 달라지는 선택만 사용자에게 질문한다.
6. diff에서 무관한 이름 변경·형식 변경·추측성 추상화가 섞이지 않았는지 확인한다.

반복 스타일 Q&A, 강제 .ai-style-rules.md 생성, CLAUDE.md나 Codex 전역 훅 설치는 하지 않는다. 지속할 규칙이 실제로 필요하면 기존 AGENTS.md에 최소한으로 반영한다. 원문의 사용 도구 목록은 권한을 부여하지 않는다.
