# Change Impact — Ned development

ECC change-impact의 프로젝트 어댑터다. 출처와 고정 원문은 ../../README.md 및 references/upstream.md를 참조한다. 이 파일의 흐름을 적용하고 원문의 반복 확인·문서 생성·별도 스킬 요구를 그대로 실행하지 않는다.

## 변경 전

1. 최신 사용자 요청에서 기대 동작과 변경하지 않을 범위를 정리한다. 이미 정해진 사항은 다시 묻지 않는다.
2. git status와 대상 diff를 확인한다. 실제 import, 호출, IPC/RPC 계약, 설정 스키마, 테스트로 연결을 추적한다. 디렉터리 이름만으로 의존성을 추정하지 않는다.
3. 관련 항목만 짧게 기록한다.
   - 코드: 진입점, 직접 호출자, 종료·취소·실패 경로.
   - 데이터: 설정 암호화, JSONC, 대화·지식·편집기 상태, 마이그레이션.
   - 계약: ACP, 호스트 도구, 모델 요청, MCP 입력·출력.
   - 배포: 고정 런타임, lock·해시, 설치·업데이트·복구, 라이선스.
   - 검증: 실제 증상을 잡는 테스트, 실행 환경, 미검증 영역.
4. 변경이 필요한 코드와 테스트를 최소 범위로 선택한다. 근거가 없는 연결은 미확인으로 표시한다.

## 변경 후

실제 diff가 요청과 예상 범위에 맞는지 비교한다. 호환성·취소·사용자 데이터 보존과 관련된 검증 근거를 확인하고, 필요한 기존 문서만 갱신한다. 롤백이 필요한 변경에서는 실제 복구 경로와 한계를 설명하되 사용자 데이터로 복구 실험을 임의 수행하지 않는다.

작은 작업은 응답으로 정리한다. 새 영향 보고서나 ADR을 매번 만들지 않는다. 승인된 구현은 계속하고 제품 결정을 바꾸는 미결 사항만 질문한다. 테스트 성공과 실제 Windows/사내 서버 수용 성공을 구분한다.
