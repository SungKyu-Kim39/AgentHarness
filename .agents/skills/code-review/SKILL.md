# Code Review — Ned development

Matt Pocock code-review의 요구사항/규칙 두 관점을 순차 리뷰로 조정했다. ../../README.md와 references/upstream.md에 출처가 있다. 원본의 자동 서브에이전트·이슈 트래커 설정 요구는 적용하지 않는다.

## 비교 범위

명시된 기준 ref가 있으면 유효한지 확인하고 merge-base부터 변경을 읽는다. 작업 중 수정 리뷰는 staged와 unstaged diff, 새 파일을 포함한다. 사용자가 기준을 주지 않았으면 현재 작업 diff나 요청한 커밋으로 범위를 정해 설명한다. main과 work가 같거나 diff가 비어 있다는 이유로 기준 질문을 반복하지 않는다.

요구사항은 최신 사용자 요청과 관련 docs/·HANDOFF의 실제 상태를 대조한다. 외부 이슈 트래커가 없어도 로컬 근거로 진행한다. 과거 문서와 현재 코드가 충돌하면 불확실성을 명시한다.

## 관점 1 — 요구사항

사용자가 요청한 동작, 누락·부분 구현, 범위 밖 변경을 살핀다. 설정 유지·호환성·실패·취소·업데이트 경로를 포함한다. 특히 Codex 개발용 스킬과 제품 번들 변경을 혼동하지 않았는지 확인한다.

## 관점 2 — 코드와 검증

인접 관례, 실제 호출 계약, 상태·자원 소유권, 경로·프로세스 식별, 권한 중계, 비밀 정보, 오프라인·버전·해시·라이선스를 변경 관련 범위에서 살핀다. 추측성 추상화·중복·복잡성은 영향이 명확할 때만 지적한다. 스타일 취향이나 자동 도구가 잡는 사항으로 실제 결함을 가리지 않는다.

실제 결함을 검출하는 테스트인지 확인한다. 코드 실행·패키지 생성·Linux 검사와 실제 Windows/사내 환경 수용 증거를 구분한다. 문서만 바꾼 작업은 링크·frontmatter·해시·변경 범위 검사로 충분할 수 있다.

## 결과

실행 경로와 파일 위치로 근거를 댈 수 있는 결함을 심각도 순으로 보고한다. 각 finding에 조건, 영향, 최소 조치를 적고 요구사항/코드 관점을 표시한다. 근거 없는 침해 주장이나 수정하지 않은 파일에 대한 추측은 제외한다. 결함이 없으면 그렇게 말하고 실제 수행한 검증과 미실행 영역을 짧게 남긴다. 리뷰를 독립 실행으로 수행하지 않았다면 독립 검토로 표현하지 않는다.
