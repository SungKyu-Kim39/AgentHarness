# Codebase Design — Ned development

Matt Pocock codebase-design의 작은 인터페이스와 깊은 모듈 원칙을 적용한다. ../../README.md와 references/upstream.md에 출처가 있다.

- 먼저 실제 호출자와 현재 계약을 읽는다. 인터페이스는 타입뿐 아니라 순서, 상태, 설정, 실패, 취소, 성능 조건까지 포함한다.
- 호출자가 알아야 하는 내용을 줄이고 반복되는 복잡성을 한 소유 모듈로 모은다. 단순 전달 계층이나 가상의 미래 변형을 위해 추상화를 추가하지 않는다.
- 프로세스·연결·승인·AbortSignal·파일 스냅샷의 소유자와 폐기 시점을 명확히 한다. 시작 실패, 요청 취소, 종료 미확인에서도 상태가 일관되어야 한다.
- 테스트는 실제 호출자가 사용하는 계약을 통과하도록 구성한다. 순수 계산과 부작용을 분리하고 필요한 의존성을 주입하되 공개 표면을 테스트 전용으로 늘리지 않는다.
- 구현 두 가지가 실제로 필요할 때 교체 지점을 만든다. 실제 사용 사례로 현재·제안 인터페이스의 복잡성을 비교한다.
- 기존 데이터·설정·ACP·도구 이름·실행 순서의 호환성을 유지한다. 리팩터링을 이유로 요청 범위를 넓히지 않는다.

설계 대안은 필요한 경우 같은 에이전트가 순차 비교한다. 원문의 자동 병렬 설계·서브에이전트 흐름이나 특정 영어 용어 사용을 강제하지 않는다. 변경에 도움이 되는 만큼만 설명하고 관련 검증을 연결한다.
