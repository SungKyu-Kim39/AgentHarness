# Ned 개발에 사용하는 Codex 스킬

이 폴더는 Ned 소스를 작업하는 Codex 프로젝트의 지침입니다. 설치본에 들어가는 스킬과 OpenViking 등록 목록은 루트의 제품 번들에서 따로 관리합니다.

저장소 루트를 Codex 프로젝트로 열면 `.agents/skills/`와 `AGENTS.md`의 작업별 연결을 사용합니다. 현재 세션에 목록이 바로 갱신되지 않으면 해당 `SKILL.md`를 직접 읽어 적용하고, 다음 세션에서 자동 발견 여부를 확인합니다.

고정 원본은 [ECC](https://github.com/affaan-m/ECC/tree/d2ef2680594f9a17526a6e1a2e18b3d242c5d17b)와 [Matt Pocock](https://github.com/mattpocock/skills/tree/5863806dd4e15c63174bee4e7515a4256792ecfa)입니다. 각 스킬의 `references/upstream.md`와 MIT `LICENSE`를 보관합니다. 이 폴더의 `skills-lock.json`에는 출처, Git blob SHA, 원문·어댑터 SHA-256을 기록하며 제품용 루트 lock과 구분합니다.

## 프로젝트에 맞춰 바꾼 부분

원본 Read·Glob·Grep·Bash는 실제 Codex의 파일 읽기·`rg`·명령 실행으로 대응합니다. 없는 MCP·셸·이슈 트래커를 설치하지 않습니다. 이미 승인한 범위에서 진행하고, 매 단계 확인이나 스타일 Q&A, 별도 `CLAUDE.md`·`settings.json` 훅을 요구하지 않습니다.

리뷰의 두 관점은 기본적으로 같은 에이전트가 순서대로 검토합니다. 자동 서브에이전트·다중 모델 호출은 추가하지 않았습니다. 기존 문서 구조를 활용하고 작업마다 보고서·스타일 파일을 새로 만들지 않습니다.

Windows나 사내 서버가 없으면 가능한 코드 조사와 재현을 진행하되 확인하지 못한 범위를 함께 기록합니다. 디버깅을 위해 사용자 앱을 강제로 닫거나 사내 모델 대기를 제한하지 않습니다. 설명에는 한국어 기술 용어를 사용할 수 있으며 특정 영단어 사용을 강제하지 않습니다.

스킬은 Markdown과 라이선스 파일입니다. 외부 설치기·실행 훅·자동 업데이트·통계 전송은 넣지 않았습니다. 이 여섯 개는 호스트와 배포 개발에 맞춰 골랐고, UI·윤문·마케팅·게임 분야는 필요한 작업에 맞춰 별도 선별할 수 있습니다.

## 원본을 갱신할 때

자동 갱신은 하지 않습니다. 고정 커밋과 새 원본의 차이를 읽고, 어댑터를 검토한 뒤 원문·라이선스·Git blob SHA·SHA-256을 함께 바꿉니다. 이 개발용 폴더를 제품 스킬 번들 스크립트의 입력으로 추가하지 않습니다.
